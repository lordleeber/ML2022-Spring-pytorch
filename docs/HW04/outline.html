寫章時要處理的 repo 問題

讀程式時找到、會變成 warn 框或練習題的地方。每一條都會在對應的章節實測或逐行指出。

  1. 「最佳」checkpoint 不是最佳的：train.py:297 是 best_state_dict = model.state_dict()，沒有 copy.deepcopy。state_dict() 回傳的是參數 tensor 的參照，所以每 10,000 步存檔時存下的都是存檔當下的權重。實測：最高的驗證準確率在第 68,000 步，第 70,000 步存下的卻是第 70,000 步的權重，log 仍印 0.6859。→ 第 4 章
  2. 印出的驗證準確率和測試時的做法不一樣：valid() 用的是隨機切出的 128 格（和訓練一樣），test.py 卻用整句。同一個模型在 5,667 句驗證集上，切段是 0.685、整句是 0.857。→ 第 0、4、5 章
  3. 驗證集 drop_last=True（train.py:101）：最後 3 句不參加驗證，進度條停在 5664/5667；準確率是各 batch 平均再平均。實測：177 個 batch 都是 32 句，所以「平均再平均」和逐句計數的結果相同。→ 第 2、4 章
  4. dropout 參數沒有用到：Classifier.__init__(..., dropout=0.1) 收了這個參數，但沒有傳給 TransformerEncoderLayer；剛好那一層的預設值也是 0.1。→ 第 3 章
  5. mean pooling 平均到補的值：pad_sequence 補 -20，模型沒有 padding mask，out.mean(dim=1) 把補的格子也算進去。訓練集只有 2 句短於 128 格，所以實際影響很小。→ 第 2、3 章
  6. 說明文字重複：classifier.py:1-23 與 train.py:109-131 是同一段 Model 說明；train.py:169 又 import torch 一次。這是 notebook 拆檔留下的痕跡。→ 第 0 章、index
  7. 投影片前後不一致：p.5 說測試集有 4,000 句（public 與 private），p.20 說要交 8,000 行；testdata.json 實際是 8,000 句。→ 第 5 章
  8. 不能宣稱過了 Kaggle 基準線：驗證準確率不等於 Kaggle 測試集分數；驗證集與訓練集是同一批說話者的句子隨機分的，可能比測試集容易。只能說「驗證集上的位置」。→ 第 0、8 章
