第 1 章　解剖 COVID 資料

模型看到的只是一個 117 欄的數字陣列，但每一欄都有來歷。本章先用 shell 與 pandas 把兩個 CSV 一欄一欄拆開：118 欄怎麼排、州別怎麼表示、16 個指標各是什麼、數值落在什麼範圍。最後挖出一個作業說明沒講的結構——每一列其實是一段滑動的時間視窗，而 id 欄偷偷記錄了時間。

接下來的 Python 指令怎麼讀

本章後面的分析都用 pandas（Python 處理表格資料的函式庫）寫成一次性的指令，格式像這樣：

$ ../.venv/bin/python -c "
import pandas as pd
d = pd.read_csv('covid.train.csv')
print(d.shape)
"

python -c "程式碼" 讓 Python 直接執行引號裡的程式，不必另存成 .py 檔。引號裡可以換行：在 bash 裡打完第一行的 " 按 Enter，終端機會顯示 > 提示你繼續輸入，直到打出收尾的 " 才執行；整段複製貼上也可以。程式裡用到的 pandas 語法只有下面幾種：

  • d = pd.read_csv(...)：把 CSV 讀成一個 DataFrame——帶欄名的二維表格，可以想成「每一欄有名字的 NumPy 陣列」。
  • d['FL']：用欄名取出一欄。
  • d.iloc[列, 欄]：用位置取值，寫法和 NumPy 切片一樣（d.iloc[:, 1:38] = 所有列、第 1～37 欄）。DataFrame 的中括號預設是拿欄名查，所以要用位置時得多寫 .iloc。
  • 印出一欄的結果時，pandas 會在最後附上 Name: …, dtype: … 一行，說明這欄叫什麼、是什麼型別，看結果時可以忽略。

1.3　州別：one-hot 編碼

「這一列是哪一州」本來是一個類別值，例如 FL。但模型只吃數字，所以要把類別轉成數字。最直覺的做法是編號（AL=1、AK=2……FL=8），但這會讓模型誤以為「FL 比 AK 大」「AK 和 AZ 很接近」——州名的編號順序沒有任何數值意義。

one-hot 編碼的做法是：37 個州開 37 欄，每一列只有自己那一州的欄是 1，其餘都是 0。這樣每一州都是一個獨立的開關，彼此沒有大小與遠近。資料裡的 37 州是：AL AK AZ AR CA CO CT FL GA ID IL IN IA KS KY LA MD MA MI MN MS MO NE NV NJ NM NY NC OH OK OR RI SC TX UT VA WA（依欄位順序，美國其餘 13 州不在資料裡）。用 pandas 驗證「每一列恰好一個 1」：

$ ../.venv/bin/python -c "
import pandas as pd
d = pd.read_csv('covid.train.csv')
states = d.iloc[:, 1:38]
print(states.sum(axis=1).value_counts())
print(states.idxmax(axis=1).value_counts().agg(['min', 'max']))
"
1    2699  «1»
Name: count, dtype: int64
min    53  «2»
max    91
Name: count, dtype: int64
  1. 1d.iloc[:, 1:38] 取 0 起算的第 1～37 欄（Python 切片不含右端點 38），正是 37 個州欄。每列橫向加總（axis=1），全部 2699 列的總和都是 1：每列恰好屬於一州。
  2. 2idxmax(axis=1) 找出每列值最大（也就是那個 1）的欄名，等於把 one-hot 轉回州名，再數每州有幾列。最少的州 53 列、最多的州 91 列，平均約 73 列。

one-hot 的代價是欄位多：37 欄裡只有 1 欄有資訊，其餘 36 欄都是 0。對 2699 筆資料來說，這 37 欄佔了輸入的三分之一。它們有沒有用？各州的陽性率確實差很多：

$ ../.venv/bin/python -c "

缺值總數是 0，所以範例程式完全不需要處理缺值，直接轉成陣列就能用。

現在的做法：標準化，而且只用訓練集的統計量

今天處理數值特徵，標準化幾乎是固定步驟：每一欄減去平均、除以標準差，讓所有欄位都落在 0 附近、尺度相近。關鍵細節是平均與標準差只能從訓練集算，再原封不動套到驗證集與測試集；如果用全部資料算，驗證集的資訊就漏進了訓練流程。以 HW01 的切分為例（拿掉第 0 欄的 id 與最後一欄答案，只標準化 116 欄特徵）：

$ ../.venv/bin/python -c "
import pandas as pd, numpy as np
from utils import train_valid_split
from config import config
tr = pd.read_csv('covid.train.csv').values
tr, va = train_valid_split(tr, config['valid_ratio'], config['seed'])
x_tr, x_va = tr[:, 1:-1], va[:, 1:-1]
mean, std = x_tr.mean(axis=0), x_tr.std(axis=0) + 1e-8
x_tr, x_va = (x_tr - mean) / std, (x_va - mean) / std
print(x_tr.mean().round(3), x_tr.std().round(3))
print(x_va.mean().round(3), x_va.std().round(3))
"

  1. 1訓練集標準化後平均恰為 0、標準差恰為 1——因為統計量就是從它算的。開頭的 True、0 是 import config 時印的。
  2. 2驗證集用的是訓練集的統計量，所以只是「接近」0 與 1。這個小落差是正常的，也正是「驗證集沒被偷看」的證據。+ 1e-8 是防止某欄標準差為 0 時除以零。

1.6　隱藏的結構：滑動視窗與 id

也就是說，資料是把每一州的每日時間序列，用寬度 5 天的視窗一次滑動一天切出來的。同一州相鄰的兩列共享 4 天的資料：

這個結構帶來三個後果，都會在後面的章節回來：

  1. id 在州內按時間遞增。id 0 → 32 → 63 → 67 是 FL 的連續日期，中間的編號屬於其他州。把同樣的檢查套到全部 37 州（指令在這份清單之後）：按 id 排序後，判斷每一列的第 1～4 天陽性率是否等於前一列的第 2～5 天，數出每州接不上的次數。結果是 29 州完全接得上；其餘 8 州各只有 1～2 處接不上（例如中間缺了一天），其他相鄰列一樣是晚一天。所以 id 不是無意義的流水號，而是一個粗略的時間刻度。
  2. 訓練集與驗證集會共享資料。第 2 章會把 2699 列隨機切成訓練與驗證。由於相鄰兩列共享 4 天，驗證集裡的一列，它的前後鄰居很可能在訓練集裡——驗證集沒有想像中那麼「沒看過」。這是用隨機切分處理時間序列的通病，範例程式沒有處理它。
  3. 某列的答案，常常就是另一列的輸入。id 0 的答案 7.456154 原封不動地出現在 id 32 的第 4 天欄位裡。

第 1 點的全州檢查指令如下。v[1:, :4] 是「第 2 列起每列的第 1～4 天」，v[:-1, 1:] 是「到倒數第 2 列為止每列的第 2～5 天」，逐列比較兩者是否相等；np.isclose 比較浮點數時容許極小的誤差。

$ ../.venv/bin/python -c "
import pandas as pd, numpy as np
d = pd.read_csv('covid.train.csv').sort_values('id')
state = d.iloc[:, 1:38].idxmax(axis=1)
tp = ['tested_positive'] + [f'tested_positive.{k}' for k in range(1, 5)]
breaks = {}
for s, g in d.groupby(state):
    v = g[tp].values
    ok = np.isclose(v[1:, :4], v[:-1, 1:]).all(axis=1)
    breaks[s] = int((~ok).sum())
b = pd.Series(breaks)
print((b == 0).sum(), 'states fully chained')
print(b[b > 0].to_dict())
"

現在的做法：照時間切驗證集

面對時間序列，今天的標準做法是用過去訓練、用未來驗證，模擬模型上線後真正面對的情況。這份資料裡 id 就是州內的時間順序，所以可以每一州各自依 id 排序，前 80% 當訓練、後 20% 當驗證：

$ ../.venv/bin/python -c "
import pandas as pd, numpy as np
d = pd.read_csv('covid.train.csv')
state = d.iloc[:, 1:38].idxmax(axis=1)
rank = d.groupby(state)['id'].rank(pct=True)
tr, va = d[rank <= 0.8].values, d[rank > 0.8].values
print(len(tr), len(va))
cols = list(range(1, 117))
X = np.c_[tr[:, cols], np.ones(len(tr))]
w = np.linalg.lstsq(X, tr[:, -1], rcond=None)[0]
pred = np.c_[va[:, cols], np.ones(len(va))] @ w
print('linreg 116 cols ', round(((pred - va[:, -1]) ** 2).mean(), 3))
print('copy day 4      ', round(((va[:, 101] - va[:, -1]) ** 2).mean(), 3))
"

對照目錄頁〈先說在前面〉在隨機切分上的結果（線性迴歸 1.166、抄第 4 天 1.313）：兩種切分的驗證集不是同一批資料，絕對數字不能直接比，但相對差距可以——隨機切分下，線性迴歸比「抄昨天」好了約 11%；照時間切，優勢只剩約 2.5%。多出來的那些特徵，在「預測未來」時幫的忙比隨機切分顯示的少得多。這正是隨機切分讓人過度樂觀的具體樣子。

讀 code 不盡信文件：id 會被當成特徵

train.py 的註解把 118 欄寫成「id + 37 states + 16 features x 5 days」，把 id 和特徵分開列。但程式在第 2 章的 select_feat 裡，select_all=True 時拿的是「答案以外的全部 117 欄」——包含第 0 欄的 id。第 0 章輸出的 number of features: 117 就是這個意思。

在訓練集裡，id 和答案有 0.264 的相關（相關係數的定義與指令在下一節；先記得它介於 −1 到 1，0.264 算弱的正向關係，遠不如前幾天陽性率的 0.98），因為 id 隱含時間，而疫情隨時間變化。模型可能真的學到「id 越大陽性率越高」。但測試集的 id 是另一套從 0 開始的編號，這條規律搬過去完全不成立。這就是為什麼作業投影片的提示頁把特徵選擇列為通過 medium 基準線（第 0 章提過的四條分數門檻中的第二條）的方法：第一個該拿掉的，就是 id。

測試集在時間上和訓練集是什麼關係？一個簡單的檢查是看測試集每列「第 1 天」的 15 個問卷值（每天 16 欄扣掉 tested_positive，只比問卷部分），有沒有和訓練集任何一列、任何一天的同樣 15 欄完全相同（以 np.isclose 判斷）：

36 of 1078

train_days 把訓練集 5 天的問卷各切出來疊成一張大表（2699 × 5 列），再逐一拿測試集的第 1 天去找。1078 列中只有 36 列找得到，和 37 州的數目相當——大約每州只在交界處重疊一列。也就是說，測試集幾乎全部是訓練集沒涵蓋的日子，只在交界處重疊一點。模型要預測的，是它沒見過的時段。

1.7　哪些欄位跟答案最有關

最後做一個簡單的相關分析：每一欄和答案 tested_positive.4 的相關係數（Pearson correlation，介於 −1 到 1，絕對值越大代表兩欄的線性關係越強）。

這組數字給了第 7 章一個清楚的方向：117 欄裡，真正扛起預測的是少數幾欄。把 37 個州欄、id、和相關很低的欄位（例如上面的 wearing_mask.4）拿掉，模型要學的東西變少、雜訊變少，通常反而更準。當然，相關係數只量線性關係，也只看單一欄；它是挑特徵的起點，不是終點。今天更常用的做法是讓模型自己回答「哪些欄位重要」，例如 permutation importance：訓練好模型後，把某一欄的值隨機打亂，看驗證 loss 變差多少——變差越多，代表模型越依賴那一欄。它能抓到非線性與欄位之間的交互作用，這是單欄相關係數做不到的。

本章重點

  • covid.train.csv 是 2699 列 × 118 欄 = id + 37 州 one-hot + 16 指標 × 5 天；covid.test.csv 少了最後一欄答案，是 1078 列 × 117 欄。
  • 16 個指標 = 4 類 COVID 症狀 + 8 行為 + 3 心理 + 1 tested_positive；前 4 天的 tested_positive 是輸入，第 5 天的是答案。
  • pandas 會把重複欄名改成 cli.1…cli.4，後綴比天數少 1；.values 轉成 float64 陣列後欄名消失，只剩位置。
  • 欄位尺度差異大（0～1、0～3、56～72、0～2699），資料沒有缺值。
  • 每一列是一州時間序列上的 5 天滑動視窗；id 在州內隨時間遞增，與答案相關 0.264，但測試集的 id 是另一套編號，不能當特徵用。
  • 與答案最相關的是前幾天的 tested_positive（第 4 天 0.985）。

自我測驗

1. 用 Python 的 0 起算索引，第 3 天的 tested_positive 是第幾欄？pandas 給它的欄名是什麼？

第 3 天的 16 欄是 70～85，tested_positive 是每天的最後一欄，所以是第 85 欄。pandas 的後綴比天數少 1，欄名是 tested_positive.2。

2. 為什麼州別要用 37 個 0/1 欄，而不是一欄 1～37 的編號？

編號會讓模型以為州之間有大小與遠近（例如 8 比 2 大、2 和 3 很接近），但州名的編號順序沒有數值意義。one-hot 讓每一州是獨立的開關，沒有虛構的順序關係。

3. 執行 .values 之後，程式要怎麼指稱「答案欄」？如果你想拿掉 id，要拿掉第幾欄？

欄名已經消失，只能用位置：答案是 [:, -1]（最後一欄）。id 是第 0 欄。

4. id 和答案在訓練集有 0.264 的正相關。為什麼這個相關性在測試集派不上用場，甚至有害？

訓練集的 id 在州內隨時間遞增，所以它隱含了訓練期間的時間資訊。測試集的 id 是從 0 重新編號的另一套，不對應同樣的時間；而且測試集幾乎全是訓練集沒涵蓋的日子。模型若學到「id 大 → 陽性率高」，搬到測試集就是錯誤的訊號。

5. 資料是滑動視窗切出來的，這對「隨機切出驗證集」有什麼影響？

同一州相鄰兩列共享 4 天的資料。隨機切分時，驗證集某列的鄰居很可能落在訓練集，模型等於已經看過驗證資料的大部分內容，驗證 loss 會比模型面對全新時段時樂觀。
