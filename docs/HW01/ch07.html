7.3　先統一量尺：本章的實驗怎麼做

要比較「改了之後有沒有變好」，第一個條件是量尺可信。第 3 章 3.5 節已經看到，範例程式印出的 valid loss 有三層偏差：最後一個 27 筆的 batch 份量被放大、valid 每個 epoch 重新打亂造成雜訊、再從雜訊裡挑最小值。拿這樣的數字比較兩個設定，差距可能只是運氣。所以本章所有改良實驗都先套用第 3 章的修法（3.6 節動手做第 4 項：train.py 第 123 行 shuffle=False、第 79 行乘上 len(y)、第 81 行除以總筆數）。這樣印出的最佳 valid loss，就等於那個 checkpoint 在 539 筆上一次算完的真實 MSE，可以直接和目錄頁的線性迴歸 1.166 比。

實驗腳本，以及它可不可信

約 70 次訓練是用一支照 train.py 流程重寫的腳本在本機 GPU 上跑的：same_seed → 切分 → 選特徵 →（標準化）→ DataLoader → 建模型 → trainer 的五步驟、存最佳、early stop，每一步都和 train.py 相同，只是把「選哪些欄、要不要標準化、用哪個優化器、模型長什麼樣」做成可切換的設定。這支腳本沒有放進 repo，所以先說它怎麼被驗證過：

  • 用原版設定跑，逐位元重現了第 0、3、4、5 章的數字：印出的最佳 1.6611、在第 1483 個 epoch、第 1883 個 epoch 停止、存檔 49 次、checkpoint 的真實 MSE 2.0685、第一層 10 個單元沒在工作。
  • 用修正量法的設定跑，也重現了第 3 章動手做的結果：最佳 1.7174、在第 2968 個 epoch、跑滿 3000 個 epoch、存檔 187 次。

7.4　medium：特徵選擇

改法有兩種。一種是 config.py 第 11 行設 'select_all': False，再把 utils.py 第 34 行的 [0, 1, 2, 3, 4] 換成你要的欄號；另一種是直接改第 32 行（第 2 章動手做拿掉 id 就是這樣改的）。不管哪一種，train.py 與 predict.py 都經由同一個 select_feat 取欄，兩邊自動一致（7.12 節會講什麼情況下不再自動一致）。例如 tp4：

        feat_idx = [53, 69, 85, 101]  # 前 4 天的 tested_positive

corr 要在函式裡現算。下面是示意寫法，依照上一節的準則（只看訓練部分、不含 id），本書沒有執行這一段：

        xs, ys = train_data[:, 1:-1], train_data[:, -1]          # 訓練部分，去掉 id 與答案
        r = np.array([abs(np.corrcoef(xs[:, j], ys)[0, 1]) for j in range(xs.shape[1])])
        feat_idx = [int(j) + 1 for j in np.where(r > 0.5)[0]]    # +1：換回含 id 的欄號；int() 轉成 Python 整數

（np.corrcoef 算兩組數字的相關係數矩陣，[0, 1] 取出兩者之間的那一個；第 1 章用的是 pandas 的 corr()，算的是同一個 Pearson 相關係數。）

7.5　標準化，然後重調學習率

標準化不在作業提示裡，但前面三章都指向它：第 1 章 1.4 節的「現在的做法」框、第 2 章「id 拖累的主因是數值尺度」、第 4 章 4.7 節「先處理輸入的尺度，再談模型」。原程式沒有做標準化的位置，要自己加。最自然的地方是 train.py 選完特徵之後、建 Dataset 之前：

示意寫法（本書沒有執行這一段；本機實驗用的是同一個做法）：

    mean, std = x_train.mean(axis=0), x_train.std(axis=0)   # 只用訓練部分算
    std[std == 0] = 1                                       # 整欄都同一個值時，避免除以 0
    x_train = (x_train - mean) / std
    x_valid = (x_valid - mean) / std                        # 驗證、測試都用訓練部分的那一組
    x_test = (x_test - mean) / std

每一欄減去平均、除以標準差（第 6 章 6.9 節：變異數開根號），所有欄位都落在 0 附近、大小相近。第 1 章 1.4 節的框強調過：平均與標準差只能從訓練部分算，原封不動套到驗證集與測試集。axis=0 表示沿著列的方向算，每一欄各得一個平均與標準差。第 1 章的版本是加上 1e-8 避免除以 0，這裡把標準差為 0 的欄改成 1，兩種寫法目的相同。

7.6　strong 之一：換優化器（Adam、AdamW）

第 5 章 5.4 節的「現在的做法」框說：今天優化器的預設選擇多半是 AdamW。這一節實測。

Adam（adaptive moment estimation）和 SGD＋momentum 一樣會記住梯度的歷史，差別在於它替每個參數各自決定步幅：除了梯度的移動平均（每一步把舊值打個折再加上新的梯度，就是 momentum buffer 那種累積），它還記錄每個參數梯度平方的移動平均，更新時把前者除以後者的平方根。某個參數的梯度一直很大，它的步幅就被縮小；一直很小，就被放大。所以 id 欄梯度大上百倍的問題（第 5 章 5.4 節），Adam 會自己縮放掉一大部分。AdamW 是 Adam 的變形，只差在 weight decay 的做法，7.8 節講。

改的是 train.py 第 34 行，例如（示意）：

    optimizer = torch.optim.Adam(model.parameters(), lr=config['learning_rate'])
    optimizer = torch.optim.AdamW(model.parameters(), lr=config['learning_rate'], weight_decay=0)

兩行擇一。學習率仍從 config.py 第 15 行讀，記得把 1e-5 改成要試的值。注意 torch.optim.AdamW 不寫 weight_decay 時預設是 0.01（PyTorch 文件），不是 0；下表「AdamW（wd 0）」那一列是明確指定 0。

Dropout：第 5 章答應的那件事

第 5 章 5.3 節說，模型裡一旦加了 Dropout，model.train() 與 model.eval() 就不只是習慣。Dropout 是一種在訓練時隨機把一部分單元的輸出設成 0 的層：每個 batch 隨機挑，被挑中的機率是 p，沒被挑中的輸出乘上 1/(1−p) 補回平均大小。模型因此不能依賴少數幾個單元，算是一種抑制「背熟訓練資料」的方法（7.8 節的 L2 是另一種）。它在訓練與評估時行為不同：training 旗標為 True 時隨機丟，為 False 時原樣通過。加法是在 ReLU 後面插一層（示意，p＝0.2 只是舉例）：

            nn.Linear(input_dim, 64),
            nn.ReLU(),
            nn.Dropout(0.2),
            nn.Linear(64, 32),

train.py 第 47 行每個 epoch 開頭的 model.train()、第 71 行與 predict.py 第 11 行的 model.eval()，這時就決定了 Dropout 有沒有作用：少了 eval()，驗證與預測也會隨機丟單元，每次結果都不同；少了 train()，第一個 epoch 之後的訓練全部沒有 Dropout。本書的實驗沒有包含 Dropout，它對 HW01 有沒有幫助、幫多少，沒有實測數字。

7.8　boss：L2 正則化（weight_decay）與多試參數

L2 正則化是在 loss 上加一項懲罰「權重太大」的項：總 loss ＝ MSE ＋ (λ/2) × (所有權重的平方和)。λ 越大，模型越傾向用小的權重。為什麼小權重比較好？權重小，輸入稍微改變時輸出也只會稍微改變，模型就比較難為了貼合訓練資料裡的個別雜訊而把函數扭得很彎；這類「在 loss 之外另加限制、讓模型不要太貼合訓練資料」的做法統稱正則化（regularization），目的和 7.7 節的 Dropout 一樣是抑制背熟。對某個權重 w 微分，多出來的那一項梯度就是 λw，所以每一步更新變成 w ← w − lr × (g ＋ λw)：除了照梯度走，還順便把權重往 0 拉一點。這就是 train.py 第 33 行 TODO 寫的兩種做法：「optimizer(weight decay...)」是讓優化器替你加這一項，「implement by your self」是自己把平方和加進 loss。

SGD 的 weight_decay 參數就是這樣做的：把 weight_decay × w 加到梯度上，再照第 5 章 5.4 節的 momentum 規則更新。第 5 章 5.2 節 print(optimizer) 看到的 weight_decay: 0，就是這個值。改法（示意）：

    optimizer = torch.optim.SGD(model.parameters(), lr=config['learning_rate'], momentum=0.9, weight_decay=1e-2)

Adam 與 AdamW：同一個 weight_decay，意思不同

Adam 的 weight_decay 也是把 wd × w 加到梯度上。問題是 Adam 接著會把梯度除以「梯度平方的移動平均的平方根」（7.6 節），這一項 wd × w 也被一起縮放：梯度一直很大的參數，被往 0 拉的力道跟著被縮小。AdamW（W 指 decoupled weight decay，「分離的權重衰減」）把兩件事拆開：Adam 的更新照算，權重衰減另外直接做 w ← w − lr × wd × w，不經過那個縮放。所以同樣寫 weight_decay=1e-2，在 Adam 和 AdamW 裡效果不同。

不能說「原版 train.py 用 seed 2 一定會壞掉」

這組實驗用的是量法修正後的設定（valid 不打亂）。直接跑原版 train.py 時，valid 的打亂每個 epoch 都會多消耗全域亂數（第 3 章 3.4 節），同一個 seed 的 batch 順序會不同，訓練軌跡也就不同。而且直接把 config 的 seed 改成 2，連切分都會換成另一份（7.3 節），驗證集已經不是同一批 539 筆。能說的只有：這套設定對 seed 很敏感，四次裡有一次失敗。config.py 第 10 行的註解說「you can pick your lucky number」，在原版設定下，這句玩笑是認真的。

拿掉 id 之後，4 個 seed 都穩定在 1.17～1.20（標準差 0.0127）。id 不只讓平均成績變差，也讓訓練變得不穩：一個欄位的梯度大上百倍（第 5 章 5.4 節），初始權重稍微不同，走向就可能完全不同。

7.12　改良要帶進 predict.py

第 6 章 6.2 節說：predict.py 用的 117，是執行當下依 config 與 select_feat 重算的，和訓練時用的特徵之間沒有任何檢查。本章的改法對 predict.py 有三種影響：

  • 改 utils.py 的 feat_idx 或 config 的 select_all：predict.py 第 34 行也呼叫同一個 select_feat，自動一致。前提是兩次執行之間沒有再改它（第 6 章 6.2 節的「安靜的錯」）。
  • 改 model.py 的結構：predict.py 第 39 行用同一個 My_Model 建模型，也自動一致。前提一樣：訓練完沒有再改 model.py。改了結構卻沒重新訓練，load_state_dict 會因為名字或形狀對不上而報錯（第 4 章 4.8 節），至少是大聲的失敗。
  • 加了標準化：這是唯一不會自動一致的。標準化只寫在 train.py 裡，predict.py 不知道要做；就算知道，它也拿不到訓練時算出的那一組平均與標準差。測試集若沒有標準化就送進模型，形狀完全對得上、不會報錯，模型卻在一個它從沒見過的尺度上做預測。這是比第 6 章 6.2 節更安靜的錯。

解法就是第 6 章 6.3 節「現在的做法」框預告的：把預測時必須原樣重用的東西，和權重一起存進 checkpoint。示意寫法（本書沒有執行）：

torch.save({
    'feat_idx': feat_idx,                       # 主程式要拿得到它（例如讓 select_feat 多回傳一個值）
    'mean': mean.tolist(), 'std': std.tolist(),    # 轉成 list 再存
    'state_dict': model.state_dict(),
}, config['save_path'])

載入端：

ckpt = torch.load(config['save_path'], map_location=device, weights_only=True)
test_data = pd.read_csv('./covid.test.csv').values
x_test = (test_data[:, ckpt['feat_idx']] - np.array(ckpt['mean'])) / np.array(ckpt['std'])
model = My_Model(input_dim=len(ckpt['feat_idx'])).to(device)
model.load_state_dict(ckpt['state_dict'])

平均與標準差用 .tolist() 轉成 Python 的 list 再存，是因為第 6 章 6.3 節的 weights_only 只放行 tensor、數字、字串、list、dict 這類純資料，NumPy 陣列不在那份清單裡。（依 6.3 節的規則推論；直接存 NumPy 陣列會不會被擋，本書沒有實測。）不存成 tensor 還有一個好處：map_location=device 會把 checkpoint 裡的 tensor 都放到 GPU 上，GPU 上的 tensor 不能直接 .numpy()（第 6 章 6.5 節），list 就沒有這個問題。這樣一來，predict.py 不需要讀訓練資料、不需要切分，也不可能用錯特徵或錯尺度。input_dim 直接是 feat_idx 的長度，不必另外存。

現在的做法：把前處理和模型綁在一起，用時間序列的交叉驗證挑設定

  • 前處理和模型是一體的。選欄、標準化這類「訓練時從資料學到參數」的步驟，今天通常和模型包成同一個物件一起存、一起載入（例如 scikit-learn 的 Pipeline）。上面那個字典是手工版本。原則是一樣的：預測端不該重新計算任何訓練時決定的東西。
  • 時間序列用滾動式的驗證。本章的時間切分只切一刀（前 80%／後 20%）。更穩的做法是切好幾刀：用前 1 段訓練、第 2 段驗證，用前 2 段訓練、第 3 段驗證……每一刀都是「用過去預測未來」，再把幾刀的結果平均（scikit-learn 的 TimeSeriesSplit）。它同時處理了 7.10 節的驗證方式問題與 7.11 節「一次說了不算」的問題。
  • 小型表格資料，先跑梯度提升樹。目錄頁說過，這類資料上常用的強基準是 XGBoost、LightGBM 這類梯度提升樹。它不是神經網路：模型是一棵接一棵的決策樹（一連串「某欄是否大於某值」的分岔，最後落到一個預測值），每一棵新樹專門修正前面所有樹加起來還剩下的誤差。它們是另外的套件，有自己的 API，也支援用驗證集做 early stop（樹加到驗證誤差不再下降就停）。本書沒有實測它們在 HW01 上的成績，三級題庫的挑戰題留給你。

自我測驗

1. 第 2 章「拿掉 id」的真實 MSE 是 1.240，本章是 1.1848。哪一個才對？

兩個都對，量的是兩次不同的訓練。第 2 章跑的是原版 train.py：挑選最佳 checkpoint 時用的是有雜訊、偏低的 valid loss（印出 0.982），挑出那一份再一次算完才是 1.240。本章先修好量法，挑選本身就用真實 MSE，每次存檔都是真的進步；而且 valid 不打亂之後，全域亂數的消耗方式不同，batch 順序與整條訓練路徑都變了（第 3 章 3.6 節）。所以 1.1848 不是「1.240 量得更準」，而是「另一次挑得更誠實的訓練」的結果。

2. 為什麼輸入標準化之後，原本的 lr 1e-5 反而讓結果變差（1.1848 → 1.2915）？

一個權重的梯度和它那一欄的數值大小成正比（第 1 章 1.4 節、第 5 章 5.4 節）。原版有 id 這種上千的欄位，梯度動輒幾千，學習率只能壓到 1e-5 才不會一步走太遠；那是被 id 逼出來的值。標準化之後所有欄位都在 0 附近，梯度回到正常的量級，1e-5 的步伐就小到 3000 個 epoch 都走不完（表上最佳在第 2994 個 epoch、跑滿上限）。換成 1e-3，第 543 個 epoch 就到最佳，1.0715。

3. Adam 與 AdamW 在 wd＝0 時結果完全相同，wd＝1e-2 時一個是 1.1181、一個是 1.1909。這說明了什麼？

兩者只差在 weight decay 的做法。Adam 把 wd × w 加進梯度，接著被「梯度平方的移動平均」一起縮放；AdamW 把權重衰減拆出來，直接做 w ← w − lr × wd × w。wd 為 0 時兩者是同一個演算法，所以每一欄都相同；wd 不為 0 時，同樣的數字代表不同的拉力。實務上的意思是：換優化器時，wd 的合適大小要重新找，不能照搬。

4. 64-32 架構在隨機切分下是 0.9909（第一名），在按時間切分下是 1.7157（輸給原版）。該交哪一個模型給 Kaggle？

測試集是訓練資料沒涵蓋、陽性率更高的「未來的日子」（第 6 章 6.9 節），按時間切分的驗證集比較接近這個情況，所以應該相信時間切分的排名，交出在那裡穩定的模型（例如 corr 的小模型或線性模型）。64-32 在時間切分下 train MSE 0.7048、valid 1.7157，是過擬合的典型樣子；它在隨機切分上的好成績，有一部分來自驗證集和訓練集是交錯的日子。不過要注意：本書沒有上傳 Kaggle，「時間切分比較能預告測試集」是推論，不是實測。

5. 時間切分下，seed 5201314 的 corr DNN 是 1.1219，線性 corr 是 1.1333。可以說「DNN 比線性模型好 0.01」嗎？

不行。4 個 seed 平均之後，corr DNN 是 1.1430（標準差 0.0171），線性 corr 是 1.1334（標準差 0.0002）：平均下來線性模型略好，DNN 只在 seed 5201314 那一次贏。差距 0.01 比 DNN 自己換 seed 的波動還小，單跑一次分不出高下。正確的說法是「兩者打平，線性模型更穩定」。

6. 在 train.py 加了標準化、重新訓練，predict.py 一行都沒改就執行。會報錯嗎？pred.csv 會對嗎？

不會報錯：特徵數沒變，模型形狀對得上，load_state_dict 照常成功。但 pred.csv 是錯的：模型是在標準化後的輸入上訓練的，predict.py 送進去的卻是原始尺度的測試集。這是比第 6 章 6.2 節「欄位換了」更安靜的錯。解法是把訓練部分算出的平均與標準差存進 checkpoint，predict.py 載入後原樣套用（7.12 節）。
