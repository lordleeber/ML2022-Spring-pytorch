0.1　作業要做什麼

投影片第 1–2 頁把作業分成兩個主題（Topic）：Topic I 解釋一個 CNN，模型與資料集沿用 HW3 的食物分類；Topic II 解釋 BERT，投影片標註它對應 HW7（HW7 是 BERT 問答作業）。BERT 是一種處理文字的模型：先把句子切成一個個 token（字或字的片段），每個 token 經過 12 層運算，每一層都為每個 token 輸出一個向量；它先在大量文字上預訓練（pre-train），再針對問答等特定任務用少量資料繼續訓練，叫微調（fine-tune）。兩個主題的任務頁（第 5 頁與第 13 頁）寫法幾乎一樣：跑範例程式、回答選擇題，你需要做到三件事：

  • 知道每一種方法的基本想法（Know the basic idea of each method）；
  • 把程式跑起來，觀察結果（Run the code and observe the results）；
  • 有些題目要改一小段程式再跑一次（For some cases, you may need to modify a small part of the code）。

換句話說，這份作業不訓練任何模型。CNN 的權重已經訓練好、放在 checkpoint.pth 裡；BERT 的兩個模型則直接從 Hugging Face（目錄頁介紹過的公開模型網站）下載。你的工作是「問」：拿已經訓練好的模型，用各種方法追問它的判斷依據，再根據畫出來的圖回答問題。

0.2　模型總覽：128×128 的圖片，經過 5 個 stage 變成 11 個分數

Topic I 的五種方法解釋的都是同一個模型，所以先把它看清楚。投影片第 4 頁只寫了「Model Structure: CNN model」，真正的結構在 model.py，類別名稱是 Classifier。這一節只看整體：每一層是什麼、資料的形狀怎麼變、參數在哪裡。model.py 的逐行細節，後面章節用到時再回來看（例如第 4 章會回來對照 cnn[6]、cnn[23] 是哪一層）。

這段程式用兩個小函式把層「批量生產」出來。building_block(indim, outdim)（第 12–17 行）回傳三個一組的層：卷積、BatchNorm、ReLU。stack_blocks(indim, outdim, block_num)（第 19–24 行）把 block_num 組這樣的三層串起來，第一組把通道數從 indim 變成 outdim，之後幾組維持 outdim，最後補一個 MaxPool。第 27–31 行呼叫它五次，本書把每一次呼叫產生的那一段叫做一個 stage（這是本書的稱呼，程式裡沒有這個名字）。五個 stage 的層全部倒進同一個 cnn_list，用 nn.Sequential 串成 self.cnn：一共 38 層，編號 0 到 37，model.cnn[6] 就是第 7 層。第 34–40 行的 self.fc 是最後的全連接部分，有 4 層。

六種層，各做一件事

整個模型只用到六種層。先用張量（tensor）的形狀來說話：PyTorch 的圖片張量排成 (N, C, H, W)，N 是一批有幾張圖、C 是通道（channel）數、H 和 W 是高與寬。一張 RGB 彩色圖有紅綠藍 3 個通道，所以 10 張 128×128 的圖疊在一起就是 (10, 3, 128, 128)。

  • nn.Conv2d(indim, outdim, 3, 1, 1)（卷積層）：目錄頁說過，卷積層裡有很多個 filter，每個 filter 是一個小小的圖案偵測器。具體地說，這裡的每個 filter 是一個 indim × 3 × 3 的權重塊，在圖上逐格滑動，每到一個位置就把底下那一小塊和權重逐元素相乘再加總、加上一個偏差（bias），得到一個數字。滑完整張圖，就得到一張和原圖一樣大的輸出圖，叫做這個 filter 的 activation（激發值；也叫 feature map）。一層有 outdim 個 filter，所以輸出有 outdim 個通道。後面三個參數 3, 1, 1 依序是 kernel 大小 3×3、步幅（stride）1 格、四周補一圈 0（padding 1）；這個組合讓輸出的長寬和輸入一樣，卷積層只改通道數，不改尺寸。
  • nn.BatchNorm2d(outdim)（批次正規化，BN）：把每個通道的數值調整成平均 0、變異數 1 左右，再乘上一個可學的倍率、加上一個可學的平移。訓練時用「這一批」的平均與變異數；推論時改用訓練過程累積下來的長期平均（running mean／running var）。這兩組長期平均存在模型裡，但不是用梯度學出來的，下面算參數量時會再碰到它們。
  • nn.ReLU()：把負數變成 0，正數原樣保留，即 max(0, x)。沒有參數。
  • nn.MaxPool2d(2, 2, 0)（最大池化）：把圖切成不重疊的 2×2 小格，每格只留最大值。長寬各減半，通道數不變。沒有參數。整個模型裡只有它會改變長寬。
  • nn.Linear(a, b)（全連接層）：把 a 個輸入數字各乘上一個權重再加總、加上偏差，算出 b 個輸出；每個輸出都連到全部 a 個輸入，所以叫全連接。參數是 a × b 個權重加 b 個偏差。
  • nn.Dropout(p=0.3)：訓練時隨機把 30% 的數值設成 0，逼模型不要依賴少數幾個特徵；推論時什麼都不做。沒有參數。

BN 和 Dropout 在「訓練」與「推論」時的行為不同，切換的開關是 model.eval()。這份作業只做推論，所以 explain_cnn.py 的每一個解釋方法開頭都先呼叫一次 model.eval()（例如 explain_cnn.py:80）：BN 改用長期平均，Dropout 關掉。這也是為什麼同一張圖不論跑幾次，模型給的分數都一樣。

輸入方框的「縮放成 128×128、像素值 0–1」是讀圖時做的前處理（dataset.py 的 Resize 與 ToTensor），第 1 章會看那段程式。

沿著圖讀一遍，有三件事值得記住：

  1. 長寬只在 MaxPool 改變。卷積層的 3, 1, 1 讓尺寸不變，所以五個 MaxPool 把 128 一路對半到 4（128 ÷ 2⁵ = 4）。通道數則由每個 stage 第一個卷積層決定：3 → 128 → 128 → 256 → 512 → 512。
  2. forward 只有三行（第 42–45 行）：先過 self.cnn，得到 (N, 512, 4, 4)；第 44 行 out.reshape(out.size()[0], -1) 保留第 0 維（N），其餘攤成一長條，-1 的意思是「這一維讓 PyTorch 自己算」，結果是 512 × 4 × 4 = 8192；最後過 self.fc。第 35 行 nn.Linear(512 * 4 * 4, 1024) 的輸入大小寫成乘式，就是在對應這個攤平。
  3. 輸出是 11 個 logits。目錄頁用一句話介紹過 logits：還沒經過 softmax 的原始分數。完整地說，最後一層 Linear 對 11 個類別各輸出一個實數，可正可負、沒有上下限，數字越大代表模型越傾向那一類；分數最大的那一類就是預測結果。要把它變成「機率」，得再過一次 softmax：對每個分數取指數 ez，再除以 11 個指數的總和，這樣 11 個數都落在 0 到 1 之間、加起來等於 1。模型本身不做 softmax，這件事在第 2 章（LIME 拿到的是 logits 不是機率）和第 3 章（loss 的梯度）都會變得重要。

11 個類別的順序是 Bread、Dairy product、Dessert、Egg、Fried food、Meat、Noodles/Pasta、Rice、Seafood、Soup、Vegetable/Fruit（投影片第 4 頁；explain_cnn.py:297 的註解也列了同一串），所以 logits 的第 0 個是 Bread 的分數，第 10 個是 Vegetable/Fruit 的分數。

參數量：先手算，再讓 PyTorch 數

參數（parameter）是模型裡用梯度訓練出來的數字：卷積的權重與偏差、BN 的倍率與平移、Linear 的權重與偏差。三種有參數的層，公式分別是：

Conv2d(c_in, c_out, 3)：3 × 3 × c_in × c_out 個權重 + c_out 個偏差
BatchNorm2d(c)：c 個倍率 + c 個平移 = 2c
Linear(a, b)：a × b 個權重 + b 個偏差

代入每一層：

Conv 3→128：9 × 3 × 128 + 128 = 3,584
Conv 128→128：9 × 128 × 128 + 128 = 147,584（共 5 個：cnn[3]、[6]、[10]、[13]、[16]）
Conv 128→256：9 × 128 × 256 + 256 = 295,168
Conv 256→256：9 × 256 × 256 + 256 = 590,080（共 2 個：cnn[23]、[26]）
Conv 256→512：9 × 256 × 512 + 512 = 1,180,160
Conv 512→512：9 × 512 × 512 + 512 = 2,359,808
11 個卷積層合計 5,756,800；11 個 BN 合計 6 × 256 + 3 × 512 + 2 × 1,024 = 5,120
cnn 合計：5,756,800 + 5,120 = 5,761,920
fc：(8,192 × 1,024 + 1,024) + (1,024 × 11 + 11) = 8,389,632 + 11,275 = 8,400,907
全模型：5,761,920 + 8,400,907 = 14,162,827

為什麼一個 Linear 就比 11 個卷積層加起來還多？因為卷積層的權重是「共用」的：同一個 3×3 的 filter 在整張圖上滑動，不管圖多大，參數都是 3 × 3 × c_in × c_out。Linear 沒有這種共用，8,192 個輸入和 1,024 個輸出之間每一對都要一個權重，於是 8,192 × 1,024 ≈ 839 萬。

參數之外：BN 的 buffer

BN 的長期平均（running mean、running var）也存在模型裡，但它們不是參數：不用梯度訓練，m.parameters() 也不會數到。PyTorch 把這類「存在模型裡、但不訓練」的張量叫做 buffer。每個 BN 有 c 個 running mean、c 個 running var，再加上一個計數器 num_batches_tracked；11 個 BN 共 2,560 個通道，所以 buffer 一共 2 × 2,560 + 11 = 5,131 個數字。存檔時參數和 buffer 會一起存下來，所以 checkpoint.pth 裡的模型權重不只 14,162,827 個數字；這個檔案裡到底裝了哪些東西，是第 1 章的開頭。

  1. 1開頭的數字是層在 model.cnn 裡的編號。五個 MaxPool 分別在 9、19、29、33、37，和逐層表一致；N = 1 因為只送了一張圖。
  2. 2卷積部分的終點：512 個通道、每個 4×4。
  3. 3攤平後 8,192 個數字進 fc，出來 11 個 logits。指令裡的 \" 是因為整段 Python 包在 shell 的雙引號裡，裡面的雙引號要跳脫。

現在的做法：用 global average pooling 取代大的全連接層

「卷積之後攤平、接一個很大的 Linear」是 2010 年代前期 CNN 常見的設計，這個模型 59% 的參數就花在這裡。之後的主流架構（例如 torchvision 內建的 ResNet）改成先做 global average pooling：把每個通道的整張小圖平均成一個數字，再接一個小 Linear。PyTorch 的寫法是 nn.AdaptiveAvgPool2d(1)。套到這個模型上，512 個 4×4 的通道會變成 512 個數字，最後只需要 Linear(512, 11)，參數是 512 × 11 + 11 = 5,643 個（手算），比原本的 8,400,907 少了一千多倍。本書解釋的是原本那個已經訓練好的模型，所以不改它；這裡只是讓你知道，今天的 CNN 大多不長這樣。

自我測驗

1. 一張 128×128 的 RGB 圖片經過 model.cnn 之後，形狀是什麼？為什麼長寬剛好是 4？

(N, 512, 4, 4)。卷積層的 kernel 3、stride 1、padding 1 不改長寬，只有 5 個 MaxPool(2, 2) 各把長寬減半：128 ÷ 2⁵ = 4。通道數 512 來自 stage 5 的卷積層 Conv 512→512。

2. 手算 cnn[23] 有幾個參數。

cnn[23] 是 stage 3 的第 2 個卷積層 Conv2d(256, 256, 3)：3 × 3 × 256 × 256 個權重 + 256 個偏差 = 589,824 + 256 = 590,080。

3. 如果把 model.py 第 35 行的 Linear 換成「先 global average pooling、再接 Linear(512, 11)」，全模型的參數會剩多少？（只手算，不用改程式。）

cnn 不變，5,761,920；新的 fc 只有 512 × 11 + 11 = 5,643；pooling 沒有參數。合計 5,767,563，大約是原本的 41%。（這是手算；本書沒有實際改模型去跑。改了之後原本的 checkpoint.pth 也載入不了，因為權重的形狀對不上。）

4. 在 repo 根目錄執行 .venv/bin/python HW09/explain_cnn.py 會怎樣？為什麼？

from model import Classifier 會成功（Python 把腳本所在的 HW09/ 加進模組搜尋路徑），但資料路徑 ./checkpoint.pth、./food/、./output/ 相對的是目前所在的資料夾，也就是 repo 根目錄：第 285 行先在根目錄建出一個 output/，第 289 行讀 ./checkpoint.pth 時找不到檔案而停止。要先 cd HW09 再用 ../.venv/bin/python explain_cnn.py。（本書沒有實際這樣跑，所以不列錯誤訊息。）

5. bert_hidden_states.py 只印了 3 行 saved …，為什麼 output/ 裡多了 36 張圖？

每組問答畫 Layer 1 到 Layer 12 共 12 張，但只在畫完後印一行；那一行裡的 {1..12} 是程式原樣印出的字，代表 1 到 12。3 組 × 12 層 = 36 張。
