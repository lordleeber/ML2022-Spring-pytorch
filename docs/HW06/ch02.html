ML2022 Spring · HW06 讀碼教材

第 2 章　生成器與判別器逐行

第 0 章看過兩個模型的形狀與參數量，這一章拆開每一層：判別器用的普通卷積怎麼把長寬減半；生成器用的轉置卷積為什麼叫「轉置」、怎麼把長寬剛好加倍、output_padding=1 是做什麼的；為什麼生成器用 ReLU、判別器用 LeakyReLU，最後各接一個 Tanh 與 Sigmoid；weights_init 把哪些層初始化成 N(0, 0.02)、又漏了哪一層；以及剛初始化、還沒訓練的兩個模型會輸出什麼。

2.1　判別器的卷積：k4、s2、p1 讓長寬減半

先從熟悉的卷積開始（HW03 講過）。一層 nn.Conv2d 的輸出長寬由四個數決定：輸入長寬 n、kernel 大小 k、stride s、padding p：

卷積的輸出長寬 = ⌊(n + 2p − k) / s⌋ + 1

判別器的前四層都是 kernel_size=4, stride=2, padding=1（discriminator.py:22 寫成具名參數，conv_bn_lrelu 第 41 行寫成 4, 2, 1）。代進去：(64 + 2 − 4) / 2 + 1 = 32，(32 + 2 − 4) / 2 + 1 = 16……每一層剛好減半，沒有餘數，所以 64 → 32 → 16 → 8 → 4。本書實測 Conv2d(3, 64, 4, 2, 1) 吃 64×64 吐 32×32，和公式一致。最後一層 Conv2d(512, 1, kernel_size=4, stride=1, padding=0)：(4 + 0 − 4) / 1 + 1 = 1，把 4×4 收成一點。

用 stride 2 的卷積來縮小，而不是「卷積 + 池化（pooling）」，是 DCGAN 論文的建議之一：讓網路自己學怎麼縮小，而不是固定取最大值或平均。HW03 的分類器用的是 max pooling；GAN 的判別器與生成器都把池化拿掉了。

2.2　轉置卷積：把卷積倒過來用

生成器要做相反的事：從 4×4 放大到 64×64。它用的是 nn.ConvTranspose2d，轉置卷積（transposed convolution）。有些文章叫它「反卷積」（deconvolution），但這個名字容易誤會——它並不是把卷積的計算「還原」回去，而是另一種有自己權重的運算；generator.py 的函式名稱 dconv_bn_relu 的 d 就是 deconvolution。

為什麼叫「轉置」：它就是卷積的反向傳播

一層卷積是一個線性運算：輸入攤平成一個長向量 x，輸出 y = C x，C 是一個由 kernel 權重排成的大矩陣。stride 2 的卷積把 16×16 變 8×8，C 就是「64 列、256 行」（再乘上 channel 數）的矩陣。把這個矩陣轉置，CT 就是「256 列、64 行」——它吃 8×8、吐 16×16。這就是轉置卷積：用同一組 kernel 權重，做卷積矩陣的轉置。

而 CT 不是新東西：反向傳播時，loss 對卷積輸入的梯度就是 CT 乘上 loss 對輸出的梯度。PyTorch 在算每一層卷積的 backward 時，本來就在做轉置卷積。本書用數值驗證這件事：

W = torch.randn(8, 4, 5, 5)                     # 卷積權重：8 個輸出 channel、4 個輸入 channel
big = torch.randn(1, 4, 16, 16, requires_grad=True)
small = F.conv2d(big, W, stride=2, padding=2)    # 16×16 → 8×8
g = torch.randn_like(small)                      # 隨便一個「對輸出的梯度」
grad, = torch.autograd.grad(small, big, g)       # 反向傳播算出對輸入的梯度
ct = F.conv_transpose2d(g, W, stride=2, padding=2, output_padding=1)   # 同一個 W 做轉置卷積

實測 grad 與 ct 的形狀都是 (1, 4, 16, 16)，兩者的最大差距是 0.00e+00——一個位元都不差（程式在 docs/tools/hw06_facts.py model）。這也解釋了第 0 章看到的權重形狀：同一個 tensor W，當卷積的權重時是 (輸出 8, 輸入 4, 5, 5)，當轉置卷積的權重時意思反過來，是 (輸入 8, 輸出 4, 5, 5)。所以生成器的 l2.0.0.weight 是 (512, 256, 5, 5)：512 進、256 出。

直觀的看法：每個輸入「蓋一個印章」

矩陣轉置的說法很精確，但不好想像。另一個等價的看法是：每一個輸入值，把整個 kernel 乘上自己，蓋到輸出上；相鄰的輸入蓋的位置相隔 stride 格；重疊的地方相加。用一維、kernel 長 5、stride 2 來看，4 個輸入會蓋出 (4 − 1) × 2 + 5 = 11 格：

寫成公式，轉置卷積的輸出長寬是：

轉置卷積的輸出長寬 = (n − 1) × s − 2p + k + output_padding

生成器的四層都是 kernel_size=5, stride=2, padding=2, output_padding=1：(4 − 1) × 2 − 4 + 5 + 1 = 8，(8 − 1) × 2 − 4 + 5 + 1 = 16，再來 32、64。每一層剛好加倍，所以第 36 行的註解寫「double height and width」。

output_padding 在做什麼

為什麼需要 output_padding？因為卷積的縮小是「多對一」的。用同樣的 k5、s2、p2 做普通卷積，輸入 16 格會得到 ⌊(16 + 4 − 5) / 2⌋ + 1 = 8 格，輸入 15 格也會得到 ⌊(15 + 4 − 5) / 2⌋ + 1 = 8 格——除法的餘數被地板函數吃掉了。反過來從 8 格放大時，轉置卷積就不知道該還原成 15 還是 16。不加 output_padding 時 PyTorch 選小的：本書實測 ConvTranspose2d(512, 256, 5, 2, 2, output_padding=0) 把 4×4 變成 7×7；加上 output_padding=1 才是 8×8。這個參數只是「在輸出的右下多留一格」，不增加任何參數。

棋盤格：重疊次數不平均

圖 2.1 的格子裡寫著每一格被幾個 kernel 蓋到：中間是 3、2、3、2 交替。kernel 大小（5）不是 stride（2）的倍數時，某些位置總是比相鄰位置多被蓋一次，二維時就形成棋盤狀的明暗格紋，叫做 checkerboard artifact。訓練好的權重可以把它補償掉，但在 GAN 訓練初期或崩潰時，常能在生成圖上看到細細的格子紋。這個生成器用的就是 k5、s2。第 5 章 mode collapse 的樣本格放大後，可以看到規則重複的格狀紋路；它是不是就是這個效應，本書沒有進一步驗證。

現在的做法：先放大，再卷積

2016 年 Odena 等人在 Distill 上的文章〈Deconvolution and Checkerboard Artifacts〉指出棋盤格的成因，建議改成「先用最近鄰或雙線性內插把圖放大兩倍，再接一層普通的 stride 1 卷積」（resize-convolution）。這樣每一格都被同樣多的 kernel 蓋到，就沒有格紋。後來的 StyleGAN 系列與 diffusion 模型的 U-Net 大多採用「內插放大 + 卷積」，轉置卷積在生成模型裡用得越來越少。

2.3　生成器逐行

  • 第 17–19 行，l1：Linear(100, 8192, bias=False) 接 BatchNorm1d(8192) 接 ReLU。這一層是生成器裡唯一的全連接層：亂數 z 的每一個數都會影響 4×4 特徵圖上的每一個位置。DCGAN 論文的做法是用一個全連接層把 z「投影並 reshape」成第一張小特徵圖，第 43 行的 view(y.size(0), -1, 4, 4) 就是那個 reshape：-1 讓 PyTorch 自己算出 8192 / 16 = 512 個 channel。
  • 第 22–24 行，l2：三個 dconv_bn_relu，channel 512 → 256 → 128 → 64、長寬 4 → 8 → 16 → 32。行尾的形狀註解是錯的：三行都寫 feature_dim * 16（= 1,024 個 channel），實際是 feature_dim * 4、* 2、* 1，也就是 256、128、64。大概是從別處複製過來沒改。
  • 第 38 行，nn.ReLU(True)：參數 True 是 inplace=True，直接改寫輸入的 tensor、不另外配置記憶體。第 19 行的 nn.ReLU() 沒有加，兩種寫法的計算結果一樣，只差記憶體。
  • 第 26–30 行，l3：最後一層轉置卷積 64 → 3、32 → 64，後面沒有 BatchNorm，直接接 nn.Tanh()。DCGAN 論文的規則是「生成器的輸出層不加 BatchNorm」：BatchNorm 會把每個 channel 拉成固定的平均與變異數，用在最後一層等於強迫每一批圖的顏色分布都一樣，畫不出整體偏紅或偏暗的圖。Tanh 把輸出壓進 (-1, 1)，配合第 1 章把真圖正規化到 [-1, 1]。
  • 第 31 行，self.apply(utils.weights_init)：建完所有層之後，對每一個子模組呼叫一次 weights_init，重設權重（2.5 節）。

剛初始化、還沒訓練的生成器會畫出什麼？本書照 train.py 的順序設好種子、建好模型，送 64 個亂數 z 進去（訓練模式）：輸出形狀 (64, 3, 64, 64)，平均 -0.051、標準差 0.270，最小 -0.942、最大 0.938，沒有任何像素的絕對值超過 0.99。也就是說，一開始的輸出是一片接近 0（換回圖片就是接近 0.5 的灰色）的雜訊，Tanh 還沒有飽和。第 0 章那張第 1 個 epoch 的樣本格，就是從這樣的灰色雜訊開始學的。

2.4　判別器逐行

  • 第 22–23 行，第一層沒有 BatchNorm：這是 DCGAN 論文的另一條規則，「判別器的輸入層不加 BatchNorm」，和生成器的輸出層對稱。直接接 LeakyReLU(0.2)。
  • LeakyReLU 而不是 ReLU：ReLU 把負數全部變成 0，負數那一側的梯度也是 0。判別器的梯度最後要一路傳回生成器（生成器就是靠「判別器覺得哪裡不像」來學的，第 3 章），梯度在任何一層被截斷，生成器就少了那部分的訊號。LeakyReLU 讓負數乘上 0.2 通過，梯度在負數那一側是 0.2 而不是 0，訊號比較不容易斷掉。生成器內部用 ReLU 沒有這個顧慮。
  • 第 24–26 行，同樣是錯的形狀註解：三行都寫 (batch, 3, …)，好像 channel 一直是 3；實際是 128、256、512，第 22 行的 (batch, 3, 32, 32) 也應該是 64。長寬的部分（32、16、8、4）是對的。
  • 第 27 行，最後的 4×4 卷積：它的一個輸出值，看的是整張 4×4×512 的特徵圖，而那張特徵圖的每一格又各自看了原圖的一大塊，所以最後的分數是根據整張 64×64 的圖算出來的：判別器給的是「整張圖像不像」的一個判斷。（後來的 PatchGAN 等設計則故意讓判別器輸出一張小圖，每一格只判斷原圖的一塊。）
  • 第 28 行，nn.Sigmoid()：把分數壓成 0 到 1 之間的機率，接下來的 nn.BCELoss（第 3 章）需要的就是機率。第 19 行的註解提醒：做 WGAN 時要把這一層拿掉（第 6 章）。

第 36–37 行的註解寫給第 7 章：WGAN-GP 不能用 BatchNorm，要換成 InstanceNorm。原因先說個大概：gradient penalty 要求判別器對每一張圖的梯度大小都接近 1，但 BatchNorm 用整批的平均與變異數做正規化，一張圖的輸出會受到同一批其他圖的影響，「單張圖的梯度」就不再只和那張圖有關。InstanceNorm 改成每張圖自己算平均與變異數，各張圖之間就不互相干擾了。第 48 行的 view(-1) 在第 0 章看過：把 (batch, 1, 1, 1) 攤成 (batch,)。

剛初始化的判別器會給什麼分數？同樣照 train.py 的種子順序，拿資料集的前 64 張真圖和剛初始化的生成器畫的 64 張假圖去問它：真圖的平均分數 0.513（最低 0.065、最高 0.899），假圖的平均分數 0.632（0.160–0.923）。兩者都在 0.5 附近亂跳，甚至假圖還比真圖高——一個沒訓練過的判別器只是在亂猜。這時判別器的 loss（真圖要接近 1、假圖要接近 0 的 BCE，兩者平均）是 0.995，生成器的 loss（假圖要接近 1 的 BCE）是 0.526。作為對照，如果判別器對每一張圖都說 0.5，兩個 loss 都是 ln 2 = 0.693。

2.5　weights_init：N(0, 0.02)，以及漏掉的那一層

module.apply(fn) 會走過模組裡的每一個子模組（包括 nn.Sequential 這種容器本身）各呼叫一次 fn。weights_init 看類別名稱決定要不要動它：

  • 名稱裡有 'Conv'：權重設成平均 0、標準差 0.02 的常態分布。Conv2d 與 ConvTranspose2d 的名稱都含 Conv，所以兩種卷積都會被處理。bias 沒有動，保留 PyTorch 預設的均勻分布。
  • 名稱裡有 'BatchNorm'：縮放 weight 設成平均 1、標準差 0.02（每個 channel 先不放大也不縮小，只加一點擾動），平移 bias 設成 0。BatchNorm1d 與 BatchNorm2d 都會被處理。
  • 其他（Linear、ReLU、Tanh、Sequential……）：什麼都不做。

N(0, 0.02) 是 DCGAN 論文的設定（「All weights were initialized from a zero-centered Normal distribution with standard deviation 0.02」）。本書實測初始化後每一層的權重：

只有生成器的第一層 Linear 沒被處理：它保留 PyTorch 對 nn.Linear 的預設初始化，均勻分布 U(−1/√100, 1/√100) = U(−0.1, 0.1)，標準差 0.1 / √3 = 0.0577，實測一致（最大的絕對值是 0.1000）。DCGAN 論文說的是「所有權重」，所以嚴格來說範例程式漏了這一層；不過它後面緊接著 BatchNorm1d，輸出會被重新正規化，權重整體大一點或小一點對下一層的影響不大，這個遺漏在實際訓練中不太要緊。判別器卷積的 bias 也沒被歸零，原因相同：後面三層都接 BatchNorm，bias 本來就會被減掉（第 0 章）。

還有一個和亂數有關的細節：weights_init 用的 normal_ 會消耗 PyTorch 的全域亂數，而生成器建立時（Generator(100) 的建構子）是先用 PyTorch 預設方法初始化每一層、再被 weights_init 覆蓋，兩次都消耗亂數。所以「先建生成器、再建判別器」的順序是逐位元重現的一部分：TrainerGAN.__init__ 先 Generator(100) 再 Discriminator(3)（第 3 章），本書的實驗工具也照這個順序。

這張表幾乎就是 DCGAN 論文的那幾條設計規則：用 stride 卷積取代池化、生成器與判別器都用 BatchNorm（但不用在生成器的輸出層與判別器的輸入層）、拿掉全連接的隱藏層、生成器用 ReLU 而輸出用 Tanh、判別器全部用 LeakyReLU。兩個網路的大小是同一個數量級（G 比 D 大將近一倍），這很重要：GAN 的訓練是兩個網路互相較勁，一方太強另一方就學不到東西。第 3 章會看到它們怎麼輪流更新，第 5 章會看到「判別器太強」時發生什麼事。

本章重點

  • 判別器的卷積 k4、s2、p1：⌊(n + 2 − 4) / 2⌋ + 1，長寬剛好減半；最後一層 4×4 卷積把 4×4 收成 1 個分數，看的是整張圖。
  • 轉置卷積就是卷積矩陣的轉置，也就是卷積的反向傳播（本書數值驗證差距 0）；直觀上是「每個輸入把 kernel 蓋到輸出上、間隔 stride、重疊相加」。輸出長寬 (n − 1)s − 2p + k + output_padding；k5、s2、p2、op1 剛好加倍，不加 output_padding 會變成 7×7。權重形狀 (輸入, 輸出, k, k)。
  • k5、s2 讓重疊次數 3、2 交替，可能產生棋盤格紋；現在的生成模型多改用「內插放大 + 卷積」。
  • DCGAN 的設計規則：生成器 ReLU + 輸出 Tanh、判別器 LeakyReLU(0.2) + 輸出 Sigmoid、生成器輸出層與判別器輸入層不加 BN。兩個檔案裡的 channel 形狀註解都是錯的。
  • weights_init：Conv 類 N(0, 0.02)、BatchNorm 類 weight N(1, 0.02)、bias 0；生成器第一層 Linear 沒被處理（保留 U(−0.1, 0.1)，標準差 0.0577）。剛初始化時生成器輸出接近 0 的雜訊（標準差 0.27），判別器對真假圖都給 0.5 附近的分數。

自我測驗

1. 把生成器四層轉置卷積的 output_padding 都改成 0，輸出會是多大？判別器吃得下嗎？

每一層變成 (n − 1) × 2 − 4 + 5 = 2n − 1：4 → 7 → 13 → 25 → 49，輸出 49×49。判別器的四層 stride 2 卷積會把 49 縮成 24 → 12 → 6 → 3，最後的 4×4 卷積蓋不上 3×3 的特徵圖，會報錯。本書實測：生成器輸出 (2, 3, 49, 49)，送進判別器得到 RuntimeError: Calculated padded input size per channel: (3 x 3). Kernel size: (4 x 4). Kernel size can't be greater than actual input size。output_padding 雖然不增加參數，卻決定了形狀能不能接得上。

2. 轉置卷積「把卷積倒過來」，那麼先做一次 k5、s2、p2 的卷積、再用同一組權重做轉置卷積，會得到原來的圖嗎？

不會。轉置卷積是卷積矩陣 C 的轉置 CT，不是反矩陣 C−1；CTCx 一般不等於 x。而且 stride 2 的卷積把 16×16 壓成 8×8，資訊已經少了四分之三，任何運算都不可能完整還原。所以「反卷積」這個名字容易誤導；生成器的轉置卷積有自己學出來的權重，它學的是「怎麼從小特徵圖畫出大圖」，和任何一個卷積的還原都沒有關係。

3. 判別器為什麼用 LeakyReLU 而不是 ReLU？生成器為什麼可以用 ReLU？

判別器的梯度要一路傳回生成器：生成器的 loss 是透過判別器算出來的，生成器的權重要更新，梯度必須穿過判別器的每一層。ReLU 在負數那一側梯度是 0，會截斷一部分訊號；LeakyReLU 在負數那一側的梯度是 0.2，訊號不會完全斷掉。生成器的 ReLU 只影響生成器自己的權重怎麼更新，而且它後面接的是 BatchNorm 正規化過的值，大約一半是正的，不會整片死掉。這是 DCGAN 論文的經驗規則。

4. weights_init 用 classname.find('Conv') != -1 判斷。如果有人在模型裡加了一個自己寫的 class ConvBlock(nn.Module)，裡面包著幾層卷積，會發生什麼事？

apply 會走到 ConvBlock 本身，它的名稱含 Conv，於是執行 m.weight.data.normal_(...)——但 ConvBlock 自己沒有 weight 這個屬性，會丟出錯誤。本書實測一個只包著一層 nn.Conv2d 的 ConvBlock：AttributeError: 'ConvBlock' object has no attribute 'weight'。用類別名稱字串比對很脆弱；比較穩的寫法是 isinstance(m, (nn.Conv2d, nn.ConvTranspose2d))。

5. 剛初始化的判別器給假圖的平均分數（0.632）比真圖（0.513）還高。這代表什麼？訓練第一步時，哪一個網路的 loss 比較大？

只代表判別器還沒學會任何東西，分數是隨機權重的副產品，沒有意義。這時判別器的 loss 是 0.995、生成器的 loss 是 0.526：判別器的 loss 比較大，因為它把假圖判得比真圖還像真的，完全答反了；生成器的 loss 小，因為它的假圖剛好被判成偏「真」。第 0 章看到的訓練第一步是 loss_D=0.929, loss_G=3.43。本書照 train.py 重現了那一步：判別器更新前，那一批真圖、假圖的平均分數是 0.516、0.613，loss_D 0.9293；判別器只用 Adam 更新一步，新畫的一批假圖分數就掉到 0.052，loss_G 變成 3.4329——印出來的 3.43 是判別器更新之後才算的，一步就讓生成器的處境差了很多（第 3 章會看到這個順序）。
