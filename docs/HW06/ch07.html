第 7 章　報告題 Q2：WGAN-GP 與梯度範數

第 6 章的 WGAN 用 weight clipping 讓 critic 保持 Lipschitz，論文自己都說這是個糟糕的辦法。WGAN-GP 換成 gradient penalty：直接要求 critic 對輸入的梯度大小接近 1。這一章先把範例程式裡空著的 gp() 寫出來，解釋為什麼要換掉 BatchNorm；然後做報告第 2 題要的圖——clipping 與 GP 兩種設定下，判別器每一層的梯度範數；最後看 WGAN-GP 的結果，以及它在這份作業裡為什麼沒有贏過 WGAN。

7.1　題目

投影片第 19 頁的報告第 2 題：

  • 畫出「Gradient norm」的結果；
  • 用訓練資料，判別器至少 4 層；
  • 畫兩種設定：weight clipping、gradient penalty；
  • Y 軸是梯度範數（取 log），X 軸是判別器的第幾層（從低到高）。

這是 WGAN-GP 論文（Gulrajani 等，2017）Figure 1(b) 的重現：論文在一個玩具資料上畫出，用 weight clipping 時判別器各層的梯度大小差了好幾個數量級，用 gradient penalty 時則大致一樣大。本章在 HW06 的動漫臉上做同一件事。第 24 頁的提示：「Use gradient penalty to replace weight clipping」「Gradient penalty accumulate gradient from an interpolated image」。

7.2　從 clipping 到 gradient penalty

第 6 章說過，WGAN 的 critic 必須是 1-Lipschitz：輸入改變多少，輸出最多改變多少。對一個可微分的函數，這等於說「對輸入的梯度大小處處不超過 1」。WGAN-GP 論文進一步證明：最佳的 critic，在真實分布與生成分布之間的連線上，梯度大小幾乎處處剛好是 1。所以與其限制權重，不如直接懲罰梯度偏離 1 的程度：

lossD = −𝔼[ D(x真) ] + 𝔼[ D(x假) ] + λ · 𝔼x̂[ ( ‖∇x̂ D(x̂)‖2 − 1 )² ]，　x̂ = α · x真 + (1 − α) · x假，α ∼ U(0, 1)
  • 前兩項和 WGAN 一樣（第 6 章）。
  • 第三項是 gradient penalty：在真圖與假圖之間隨機取一點 x̂（每對圖各取一個 α），算 critic 在那一點對輸入圖的梯度，梯度大小離 1 越遠罰越重。不可能檢查「所有」點，論文的做法是只在真假之間的連線上抽樣——那正是生成器要走的方向。
  • 論文的設定：λ = 10；拿掉 clipping；優化器換回 Adam，學習率 1×10−4、β1 = 0、β2 = 0.9；n_critic 5；critic 裡不用 BatchNorm（7.4 節）。本書照這組設定跑。

就算把參數補上，pass 也會回傳 None，加到 loss 上又是另一個錯誤。所以 gp() 要從頭寫。本書實驗工具裡的版本：

  • 第 95 行：每一張圖各取一個 0–1 之間的 α，形狀 (bs, 1, 1, 1)，乘上 (bs, 3, 64, 64) 的圖時會自動擴展到每個像素——同一張圖的所有像素用同一個 α，所以 x̂ 是一張「兩張圖疊在一起」的半透明圖。這一行消耗全域亂數，所以 WGAN-GP 的亂數順序從第一步起就和其他設定不同了。
  • 第 96 行：假圖先 detach()，這一項只用來訓練 critic，不需要往生成器傳梯度（第 3 章）；requires_grad_(True) 讓 PyTorch 記錄「對 x̂ 的梯度」。
  • 第 98 行，torch.autograd.grad：算 critic 的輸出對輸入圖 x̂ 的梯度，而不是對權重。grad_outputs=torch.ones_like(out) 等於對 out.sum() 微分，每張圖的梯度各自獨立（前提是一張圖的輸出只和那張圖有關——7.4 節）。關鍵是 create_graph=True：penalty 是梯度的函數，等一下 loss_D.backward() 要再對它微分一次，所以這個梯度本身也要留下計算圖。這叫做二次反向傳播（double backprop），是 WGAN-GP 變慢的主因。
  • 第 99 行：把每張圖的梯度攤平成 12,288 維的向量、取 L2 範數，減 1、平方、平均，再乘 λ = 10。

放進訓練迴圈只要一行（工具第 125–126 行：if args.model_type == 'WGANGP': loss_D = loss_D + gradient_penalty(r_imgs, f_imgs)）。改在 repo 的 trainer_gan.py 上，就是把這個函式改寫成 def gp(self, r_imgs, f_imgs)（把 D 換成 self.D、λ 寫成常數或放進 config），再照註解把 loss 換掉。

7.4　為什麼要把 BatchNorm 換成 InstanceNorm

gradient penalty 要的是「critic 對每一張圖的梯度」。但 BatchNorm 在訓練模式下用整批的平均與變異數做正規化，一張圖的輸出會受到同一批其他 63 張圖的影響；這時對一張圖的輸入微分，算出來的其實是「這一批整體」的函數的梯度，不是 critic 對那一張圖的梯度，penalty 罰的就不是論文要的東西。WGAN-GP 論文因此建議 critic 不用 BatchNorm，改用 layer normalization 之類「每個樣本自己正規化」的方法。範例程式的提示是 InstanceNorm：每張圖、每個 channel 各自算平均與變異數，圖與圖之間不互相干擾。本書的工具在建完模型之後把三個 BatchNorm 換掉：

affine=True 讓 InstanceNorm 和 BatchNorm 一樣有每個 channel 的縮放與平移參數（PyTorch 的 InstanceNorm2d 預設沒有），初始值是 1 與 0，不消耗亂數，所以三種 GAN 仍然從同一組卷積權重出發。一個細節：最深的那一層特徵圖只有 4×4，InstanceNorm 在每個 channel 上只用 16 個數算平均與變異數，比 BatchNorm 用 64 張 × 16 = 1,024 個數粗糙得多。本書沒有跑「WGAN-GP 但保留 BatchNorm」的對照，所以不知道在這份資料上不換會差多少。

7.5　報告要的圖：各層的梯度範數

本書的實驗工具在訓練中每 100 步記一次判別器 5 個卷積層的權重梯度的 L2 範數（工具第 129–130 行，在 loss_D.backward() 之後、opt_D.step() 之前讀 .grad；WGAN-GP 的 loss 包含 penalty 那一項）。資料就是訓練資料，每一筆是一批 64 張真圖與 64 張假圖。下圖取第 91–100 個 epoch 的 111 筆紀錄，點是中位數，直線是四分位距：

設定conv1conv2conv3conv4conv5（輸出）conv1 ÷ conv4

clipping 的那條線從輸入端的 49.5 一路掉到 conv4 的 0.316，每往輸出走一層就縮小約 2.7–12 倍；GP 的那條線在中間三層幾乎是平的。這和 WGAN-GP 論文 Figure 1(b) 的結論一致：weight clipping 讓梯度在層與層之間爆炸或消失，gradient penalty 讓各層的梯度大小保持在同一個量級。第 6 章看過原因的一部分：clipping 把最深幾層的權重幾乎全部壓在 ±0.01 的邊界上（conv4 後面那個 BatchNorm 的縮放參數 100% 被截到 0.01），訊號每經過一層就被縮小一次，反向傳播時梯度也就一層一層地被壓小或放大。

讀這張圖時要注意的事

  • 比的是「形狀」，不是絕對大小。這是權重梯度的範數，而各層的權重數量差很多：conv1 只有 3,072 個權重，conv4 有 2,097,152 個（第 0 章）。所以重點是「各層之間平不平衡」，不是哪一條線比較高。
  • 這是訓練中的紀錄，每一筆用的是當下那一批資料，四分位距反映了批與批之間的變動。如果要像論文一樣用固定的資料與固定的模型畫，可以載入最後的存檔、拿一批訓練資料算一次；趨勢相同。
  • 訓練初期的形狀不同：第 1 個 epoch 的中位數，clipping 是 9.12、2.69、0.73、0.136、1.34，GP 是 68.6、53.5、24.4、12.8、7.55——GP 一開始梯度很大，被 penalty 壓了一陣子才穩定在 13–14；clipping 從一開始就是失衡的。

另一個角度：critic 對輸入的梯度

gradient penalty 直接管的是「critic 對輸入圖的梯度」，不是權重梯度。本書載入兩種設定在第 1、50、100 個 epoch 的存檔（critic 與對應的生成器），拿 256 張隨機真圖、256 張生成圖與它們的內插點，算每張圖的 ‖∇xD(x)‖：

（平均 ± 標準差；critic 用訓練模式，與訓練時相同。）GP 的 critic 在內插點上的梯度從第 50 個 epoch 起穩定在 1.2 左右，接近 penalty 要求的 1；clipping 的 critic 一開始只有 0.2，遠小於 1——critic 被 clipping 限制得太「平」，給生成器的訊號很弱——之後又一路漂到 1.34，沒有任何機制把它固定在某個值。這就是論文說的「clipping 不是 Lipschitz 限制的好辦法」：它限制的是權重，而權重和真正想控制的輸入梯度之間，隔著整個網路的結構。

WGAN-GP 論文的實驗裡它通常比 clipping 好，這裡卻差一點。本書不能從一次訓練推論「clipping 比較好」，可能的原因很多：兩者的優化器與學習率不同（RMSProp 5e-5 對 Adam 1e-4、β 0/0.9，都是照各自論文的設定，沒有為這份資料調過）；WGAN-GP 換掉了 BatchNorm，判別器的結構也不同了；兩條曲線到第 100 個 epoch 都還在下降，「誰先跑到哪裡」不等於「誰最後比較好」；而且每種設定都只跑了一個種子。能確定的是：兩者都解決了 DCGAN 的崩潰問題，GP 的梯度在各層之間平衡得多，而它的代價是兩倍多的時間。

7.7　報告第 2 題怎麼寫

  1. 怎麼量：用訓練資料，在 loss_D.backward() 之後、opt_D.step() 之前，讀判別器每一層卷積權重的 .grad，取 L2 範數（本書每 100 步記一次，取最後 10 個 epoch 的中位數；也可以用最後的存檔對一批資料算一次）。判別器有 5 層卷積，符合「至少 4 層」。
  2. 怎麼畫：X 軸 conv1 到 conv5（從輸入到輸出），Y 軸取 log，clipping 與 GP 各一條線（圖 7.1）。
  3. 怎麼解讀：weight clipping 讓各層梯度大小相差兩個數量級（本書 conv1 ÷ conv4 = 157），越靠近輸出越小，是論文說的梯度消失／爆炸；gradient penalty 讓各層梯度保持同一量級（中間三層都在 13–14，conv1 ÷ conv4 = 2.4）。原因：clipping 只限制權重，最深的幾層權重全部卡在邊界，訊號與梯度一層層被縮放；GP 直接約束 critic 對輸入的梯度大小，critic 在真假圖的內插點上的梯度穩定在約 1.2。

現在的做法：更便宜的梯度懲罰

gradient penalty 的想法留了下來，但形式變了。Mescheder 等（2018）的 R1 regularization 只在真圖上懲罰判別器的梯度（‖∇D(x真)‖²，目標是 0 而不是 1），不需要內插，搭配原始 GAN 的 non-saturating loss；StyleGAN2 用的就是它，而且採用「lazy regularization」——每 16 步才算一次 penalty，把二次反向傳播的成本攤掉。第 8 章用的 StyleGAN2（lucidrains 的實作）在訓練 log 裡印的 GP 也是這一類：它的 gradient_penalty 以 0 為目標（和 R1 一樣，不是 WGAN-GP 的 1）、權重 10，但對真圖與生成圖都算，每 4 步算一次。

本章重點

  • WGAN-GP 把 weight clipping 換成 gradient penalty：在真假圖的隨機內插點 x̂ 上，懲罰 λ(‖∇x̂D(x̂)‖ − 1)²，λ = 10；搭配 Adam 1e-4、β (0, 0.9)、n_critic 5、不用 BatchNorm。
  • 範例程式的 gp() 是空的，簽名又和註解的呼叫方式對不上：照註解改會 TypeError: TrainerGAN.gp() takes 1 positional argument but 3 were given。實作要點：每張圖一個 α、假圖 detach()、autograd.grad(..., create_graph=True) 對輸入微分、每張圖攤平取範數。
  • BatchNorm 讓一張圖的輸出依賴同一批其他圖，「單張圖的梯度」就不成立，所以要換成 InstanceNorm（affine=True）。
  • 報告第 2 題：clipping 的各層權重梯度範數 49.5、18.2、3.68、0.316、0.614（conv1 ÷ conv4 = 157）；GP 是 32.7、13.8、12.9、13.9、5.21（2.4）。critic 在內插點上對輸入的梯度：GP 穩定在約 1.2，clipping 從 0.2 漂到 1.34。
  • WGAN-GP 不崩潰，最好 FID64 94.1（第 95 個 epoch），比這一次的 WGAN（90.3）差約 4，每 epoch 26.5 秒（WGAN 的 2.2 倍）。單次訓練、未調參，不能據此說 clipping 比較好。

自我測驗

1. 如果把第 98 行的 create_graph=True 拿掉，會發生什麼事？

autograd.grad 算出的梯度就不帶計算圖，penalty 對判別器的權重來說變成一個常數。loss_D.backward() 時這一項對權重的梯度是 0，等於沒有 gradient penalty——又因為 WGAN-GP 拿掉了 clipping，critic 完全沒有 Lipschitz 限制。程式不會報錯，只是 penalty 悄悄失效，數值上 loss 裡仍然看得到它。這題是推論，本書沒有實際跑。

2. 為什麼 penalty 要在真圖與假圖的內插點上算，而不是只在真圖或只在假圖上算？

WGAN-GP 論文證明最佳 critic 的梯度大小在真假分布之間的連線上幾乎處處是 1，而生成器的梯度正是沿著「假圖往真圖」的方向走，所以那一帶的 critic 最需要守規矩。只檢查真圖或假圖那兩個點，管不到中間的區域。後來的 R1 regularization 選擇只管真圖附近，但它要求的是梯度接近 0，是不同的理論出發點（7.7 節的方框）。

3. 第 95 行的 α 為什麼是形狀 (bs, 1, 1, 1)，而不是一個純量，也不是 (bs, 3, 64, 64)？

一個純量會讓整批 64 對圖都取同一個比例，抽樣太少；(bs, 3, 64, 64) 會讓每個像素各取一個比例，內插出來的圖不在任何一條「真圖到假圖的直線」上，而是兩張圖逐像素亂混。(bs, 1, 1, 1) 讓每一對圖各取一個比例、同一張圖的所有像素用同一個，x̂ 就落在那一對圖之間的連線上，符合論文的定義。

4. WGAN-GP 每個 epoch 26.5 秒，WGAN 11.9 秒。兩者的 n_critic 都是 5，多出來的時間花在哪裡？

主要是 gradient penalty：判別器每一步要額外對內插圖做一次 forward、用 create_graph=True 算一次對輸入的梯度（等於一次帶計算圖的 backward），然後 loss_D.backward() 時再對這個梯度反向傳播一次（二次反向傳播）。InstanceNorm 與 BatchNorm 的計算量差不多，Adam 與 RMSProp 也差不多，不是主因。本書只量了總時間，沒有逐項拆解。

5. 圖 7.1 裡 clipping 的 conv1 梯度範數（49.5）比 GP（32.7）大。能不能說「clipping 讓輸入層學得比較快」？

不能這樣解讀。兩種設定的 loss 大小不同（GP 的 loss 多了 penalty 項）、優化器不同（RMSProp 會依梯度的歷史大小重新縮放更新量，Adam 也是），所以梯度範數的絕對大小不等於實際的更新幅度。這張圖要看的是同一條線上「各層之間的比例」：clipping 的 conv1 是 conv4 的 157 倍，GP 只有 2.4 倍。
