0.1　作業要做什麼

投影片第 4 頁把作業分成兩步：第一步「從原始波形抽出 MFCC 特徵」，助教已經做好了；第二步「用這些特徵做逐音框的音素分類（framewise phoneme classification）」，這才是你要做的事。

先把三個名詞講清楚：

  • 音素（phoneme）：語言裡能區分意思的最小聲音單位。投影片第 5 頁的例子是 bat／pat、bad／bed：只差一個音，就是不同的字。「Machine Learning」拆成音素是 M AH SH IH N L ER N IH NG。這份資料一共有 41 類，程式裡用 0 到 40 的整數代表；投影片和 repo 都沒有給「哪個數字是哪個音素」的對照表，本書也不去猜。
  • 音框（frame）：把聲音切成很短的一小段，每一段叫一格（一個音框）。投影片第 8 頁說每格只有 25 毫秒（ms）。一個音素通常持續好幾格，所以投影片把「Machine」寫成 M M M AH AH SH SH IH IH IH N N N N …：每個字母代表一格。
  • MFCC（Mel Frequency Cepstral Coefficients）：從一格聲音算出來的一組數字，粗略描述這一格「聽起來像什麼」。這份資料每格是 39 個數字。MFCC 怎麼算不在作業範圍內，第 1 章只交代讀程式需要知道的部分。

所以這份作業的輸入與輸出是：輸入一格的 39 個數字（加上它前後的格子），輸出 0 到 40 其中一個整數。評分用的是 accuracy（準確率，答對的格數除以總格數）。

0.2　模型總覽：11 格 × 39 個數字，經過 10 層 LSTM 變成 11 組分數

本 repo 的模型在 model.py，類別名稱是 Classifier。這一節只看整體：有哪些層、資料的形狀怎麼變、參數在哪裡。LSTM 內部怎麼運作、這段程式哪裡和設定對不上，留給第 4 章逐行拆。

整個模型只有兩個部件：第 8–14 行的 self.lstm，和第 15 行的 self.out。註解是簡體中文，而且有幾句和這份作業對不上（例如第 9 行說「圖片每行的資料像素點」，這份作業根本沒有圖片），原因第 4 章會說明；這裡先只看程式本身。

兩個部件，各做一件事

  • nn.LSTM：LSTM（Long Short-Term Memory）是一種 RNN（recurrent neural network，循環神經網路）。它依序讀一串向量，每讀一個，就根據「這一個輸入」和「到目前為止記住的東西」更新自己的記憶，並輸出一個向量。這裡的「一串」是 11 格音框，每格 39 個數字（input_size=39），每格輸出 512 個數字（hidden_size=hidden_dim，config.py 設成 512）。num_layers=10 表示疊 10 層：第 1 層的 11 個輸出，當作第 2 層的 11 個輸入，依此類推。dropout=0.5 只在層與層之間、而且只在訓練時，隨機把一半的數值設成 0。
  • nn.Linear(hidden_dim, output_dim)：全連接層，把每格的 512 個數字變成 41 個分數，每個分數對應一個音素類別。這 41 個分數還沒經過 softmax，叫做 logits；分數最大的那一類就是模型的答案。

第 22 行 self.lstm(x, None) 回傳兩樣東西：lstm_out 是最後一層在 11 格上的輸出；(h_n, h_c) 是每一層讀完最後一格時的記憶狀態。第 28 行只用 lstm_out，而且把 11 格全部送進 self.out，所以模型對 11 格每一格都輸出 41 個分數。第 27 行被註解掉的 - original 是原本「只取最後一格」的寫法，本 repo 沒有用。

這裡有一個後面會反覆用到的事實：這個 LSTM 是單向的，它從第 1 格讀到第 11 格，所以第 k 格的輸出只看得到第 1 到第 k 格。而 train.py 拿來算準確率的是中間那一格（第 6 格），它看不到後面 5 格。這件事對分數的影響有多大，第 4 章和第 7 章會實測。

參數量：先手算，再讓 PyTorch 數

一層 LSTM 裡有 4 組「閘」（gate），第 4 章會逐一說明它們在做什麼；算參數時只要知道：每一組閘都要看「這一格的輸入」和「上一格的輸出」兩樣東西，各配一個權重矩陣，再各配一組偏差（bias）。PyTorch 把 4 組閘的權重疊在一起存，所以矩陣的列數是 4 × 512 = 2048。設這一層的輸入維度是 d、hidden 大小是 h：

一層 LSTM 的參數 = 4h × d（看輸入的權重 weight_ih）+ 4h × h（看上一格輸出的權重 weight_hh）+ 4h（bias_ih）+ 4h（bias_hh）
  • 第 0 層（d = 39、h = 512）：2048 × 39 + 2048 × 512 + 2048 + 2048 = 79,872 + 1,048,576 + 4,096 = 1,132,544。
  • 第 1–9 層（d = 512，因為輸入是上一層的輸出）：2048 × 512 + 2048 × 512 + 4,096 = 1,048,576 + 1,048,576 + 4,096 = 2,101,248，9 層共 18,911,232。
  • Linear：512 × 41 個權重 + 41 個偏差 = 20,992 + 41 = 21,033。
  • 合計：1,132,544 + 18,911,232 + 21,033 = 20,064,809，大約兩千萬個。

PyTorch 的 LSTM 有兩組偏差（bias_ih 與 bias_hh），數學上合併成一組效果相同，但它就是存兩組，手算時不要漏掉。接著讓 PyTorch 自己數，在 HW02/ 裡執行：

$ cd HW02
$ ../.venv/bin/python -c "
from model import Classifier
m = Classifier(input_dim=429, hidden_layers=1, hidden_dim=512)
for name, p in m.named_parameters():
    if name.endswith('_l0') or name.startswith('out'):
        print(name, tuple(p.shape), p.numel())
print('total', sum(p.numel() for p in m.parameters()))
"

實測輸出：

lstm.weight_ih_l0 (2048, 39) 79872

lstm.bias_ih_l0 (2048,) 2048

和手算一致。這段程式傳的三個參數照抄 train.py:38（input_dim 是 39 × 11 = 429、hidden_layers 是 1、hidden_dim 是 512），但從輸出可以看出，真正決定形狀的只有 hidden_dim：input_size 和 num_layers 都是 model.py 裡寫死的 39 和 10。config.py 寫著 hidden_layers = 1，模型卻有 10 層，這是第 4 章要處理的第一個「設定和程式對不上」。

拿來對照：原版範例程式的全連接網路只有 86,569 個參數（輸入 39、hidden 256、1 個 hidden layer，第 7 章會跑它）；本 repo 的模型是它的 232 倍。存下來的 checkpoint model.ckpt 是 80,264,975 bytes，差不多就是 20,064,809 個 float32 × 4 bytes，再加上每個參數名稱等少量額外資訊。

  2. 2最後一個 epoch。Train Acc 一路爬到 0.690659，Val Acc 從第 11 個 epoch 起就停在 0.639–0.642 之間，val loss 則從第 11 個 epoch 的 1.291020 慢慢往上升：模型開始記住訓練資料的細節，而這些細節對驗證集沒有幫助。這個現象叫過擬合（overfitting），第 5 章會再回來看這條曲線。

stderr 上另外有 tqdm 進度條（tqdm 是在終端機畫進度條的套件）：先是讀檔時的兩條（3857it [00:08, …]、429it [00:00, …]，讀完 4,286 個檔案不到 10 秒），然後每個 epoch 兩條，訓練一條數到 37182/37182、驗證一條數到 4134/4134，那是一個 epoch 的 batch 數（第 3 章）。除了進度條，stderr 沒有任何警告。

跑多久：本書在 /usr/bin/time -v 底下跑完整個 train.py，wall clock（牆上時鐘實際經過的時間）是 3 小時 4 分 48 秒。但那一次 GPU 前半段同時還有其他訓練在跑，所以 3 小時只能當作上限；後半段 GPU 只剩它自己的時候，每個 epoch 的訓練約 8 分 20 秒、驗證約 15 秒。 也就是說，改一個設定、重跑一次完整訓練，要以小時計。這也是第 7 章的對照實驗改用 5 個 epoch 的原因。

同樣的程式，同樣的結果

這份 repo 裡被忽略的 model.ckpt 是 2026-10-03 跑出來的；本書 2026-10-04 再跑一次，得到的 model.ckpt 和它逐位元組相同。原因是 same_seeds 固定了所有亂數，並要求 cuDNN 使用確定性（deterministic）的演算法（第 5 章）。所以只要環境相同，你跑出來的每一行數字都會和上面一樣；換了顯示卡或套件版本，小數點後幾位才可能不同。

本章重點

  • HW02 是逐音框音素分類：每格 25 ms、39 個 MFCC 數字，猜 41 類中的一類，評估指標是 accuracy。
  • Kaggle 四條基準線：simple 0.45797、medium 0.69747、strong 0.75028、boss 0.82324；報告兩題（窄深 vs 寬淺、三種 dropout）在第 7 章實測。
  • 模型是 10 層 LSTM（hidden 512、層間 dropout 0.5）加一個 Linear(512, 41)，對 11 格每一格都輸出 41 個分數；評估只取中間那格。
  • 參數 20,064,809 個（手算與 PyTorch 一致）：第 0 層 1,132,544，第 1–9 層各 2,101,248，Linear 21,033。
  • config.py 的 hidden_layers = 1 沒有作用，層數寫死在 model.py（第 4 章）。
  • 兩支腳本都要在 HW02/ 裡用 ../.venv/bin/python 執行，需要 NVIDIA GPU。資料與 checkpoint 被 .gitignore 擋在 repo 外，prediction.csv 例外地被追蹤。
  • 完整訓練要以小時計（實測 3 小時 4 分 48 秒，有其他工作干擾）；最佳是第 15 個 epoch，驗證準確率 0.641955，結果可以逐位元組重現。

自我測驗

1. 一個 batch 進模型之前是 (64, 429)，從 self.out 出來是什麼形狀？如果評估時只取中間那格呢？

(64, 429) 先被 train.py:58 改成 (64, 11, 39)，LSTM 輸出 (64, 11, 512)，self.out 對每一格各算一次，得到 (64, 11, 41)。評估時取 outputs[:, 5, :]，是 (64, 41)；再取最大值，得到 64 個 0–40 的類別。

2. 手算 LSTM 第 3 層有幾個參數。如果把 hidden_dim 改成 256，第 3 層會剩多少？

第 3 層的輸入是上一層的 512 維輸出：2048 × 512 + 2048 × 512 + 2048 + 2048 = 2,101,248。hidden 改成 256 時，4h = 1024、輸入也變成 256：1024 × 256 + 1024 × 256 + 1024 + 1024 = 526,336，大約剩四分之一，因為兩個權重矩陣都和 h 的平方成正比。（這題只手算，本書沒有實際改設定去跑。）

3. 在 repo 根目錄直接執行 .venv/bin/python HW02/train.py 會怎樣？

import 沒有問題（Python 會把腳本所在的 HW02/ 加進模組搜尋路徑），但 preprocess_data 用的是相對路徑 ./libriphone，相對於 repo 根目錄就找不到。實測最後一行是 FileNotFoundError: [Errno 2] No such file or directory: './libriphone/train_labels.txt'，出錯的位置是 utils.py 第 48 行讀標籤檔的地方。要先 cd HW02 再執行。

4. 20 個 epoch 裡，saving model … 印了幾次？最後 model.ckpt 存的是第幾個 epoch 的權重？

11 次：第 1 到第 9 個 epoch 每次都創新高，接著是第 11 和第 15 個 epoch。第 15 個 epoch 的 0.641955 之後就沒有再被超過，所以 model.ckpt 是第 15 個 epoch 的權重。注意第 20 個 epoch 的 0.641936 只比它低一點點，但「沒有大於」就不會存。

5. 用 repo 附的 model.ckpt 重跑 predict.py，git status 會不會出現 prediction.csv？為什麼這個檔案明明符合 *.csv，還會被 git 管？

不會。實測重跑得到的 prediction.csv 和 repo 裡的逐位元組相同，git 看不出差別。它會被 git 管，是因為它在 2022-03-09 就被 commit 進來，HW02/.gitignore 到 2022-09-29 才加入；.gitignore 只對還沒被追蹤的檔案有效。
