第 3 章　老師：ResNet-18 與它的輸出分布

知識蒸餾的效果，上限是老師給得出多少「標籤以外的資訊」。這一章在動手寫蒸餾之前，先把老師徹底量一遍：它的結構、它在驗證集上錯在哪裡、它的機率分布長什麼樣子，以及溫度 T 怎麼改變這個分布。途中會遇到兩件事：一個讓老師悄悄變笨的陷阱，和一個讓「T = 1 的蒸餾」幾乎等於沒蒸餾的事實。

3.1　ResNet-18：殘差區塊疊四層

老師是 torchvision 內建的 ResNet-18（He 等，2015），只把最後的全連接層改成 11 類（第 0 章）。它的主幹是 _forward_impl：

先用一個步幅 2 的 7×7 卷積和一個步幅 2 的 max pooling，把 224×224 縮成 56×56（第 268–271 行）；接著是四個 stage（layer1–layer4），每個 stage 由兩個 BasicBlock 組成；最後全域平均池化、攤平、全連接。四個 stage 的通道數是 64、128、256、512，從 layer2 起每個 stage 的第一個區塊步幅為 2，邊長減半。第 2 章量過，這個「先縮小、再加通道」的設計讓三個 stage 的計算量剛好相同。

BasicBlock 是兩個 3×3 卷積加上一條殘差連接（residual connection）：第 90 行先把輸入存成 identity，算完兩層卷積之後在第 102 行加回去，再過 ReLU。如果這個區塊改變了形狀（步幅 2 或通道加倍），identity 就要先經過 downsample（一個步幅 2 的 1×1 卷積加 BatchNorm，第 99–100 行）才能相加。殘差連接讓梯度可以繞過卷積直接往回傳，所以很深的網路也訓練得動；HW03 教材第 7 章做過的報告題就是在 HW03 的 CNN 上手動加這種連接。

ResNet-18 的「18」是有權重的層數：第一個卷積 1 層、四個 stage 各 2 個區塊 × 2 層卷積共 16 層、最後的全連接 1 層。downsample 裡的 1×1 卷積不算在內。torchvision 的卷積都沒有 bias（後面緊接 BatchNorm，bias 會被 BN 的平均值抵消，放了也是白放），這也是老師的卷積參數裡沒有 bias 的原因（有 bias 的只有 BatchNorm 的 β 與最後的全連接層）。

這個老師是助教自己訓練的，不是 ImageNet 預訓練的權重（規則禁止預訓練模型）。checkpoint 裡每個 BatchNorm 的 num_batches_tracked 都是 72,813，表示它被訓練了 72,813 步；如果 batch 是 64，大約是 470 個 epoch。訓練時用了什麼增強、什麼學習率，助教沒有公開。

3.3　一個讓老師變笨的陷阱：在訓練模式下呼叫 summary

本書在 Phase 0 量老師的時候，得到的是 0.86093，比上面的數字低了 1 個百分點。原因是量之前，工具先對老師呼叫了 torchsummary 來數參數。第 2 章讀過，torchsummary 會餵一筆 torch.rand(2, 3, 224, 224) 的假資料跑一次 forward。剛從 get_teacher_model() 拿到的模型處在訓練模式（model.training 為 True，nn.Module 建立時的預設），而訓練模式下的 BatchNorm 每做一次 forward，就會用這一批資料的平均與變異數去更新 running mean 與 running var：

running_mean ← 0.9 · running_mean + 0.1 · 這一批的平均
running_var ← 0.9 · running_var + 0.1 · 這一批的變異數

那一批是 [0, 1) 的均勻亂數，和真正的照片（經過 ImageNet 正規化，大致落在 −2.1 到 2.6 之間）長得完全不一樣。老師 72,813 步累積出來的統計量，就這樣被一筆垃圾資料拉走了 10%。實測：

做法驗證準確率說明
剛載入，直接 eval() 推論0.87143（2,989）正確的數字
剛載入，先 summary(...) 再 eval() 推論0.86327（2,961）bn1 的 running var 最多被改了 1.28，num_batches_tracked 從 72,813 變成 72,814
本書 Phase 0 的第一版工具（同上，另一筆亂數）0.86093（2,953）假資料不同，傷害也不同

這個陷阱就藏在範例程式裡。第 0 章引用過的 get_teacher_model() 最後一行是一個被註解掉的 # summary(teacher_model, (3, 224, 224), device='cpu')，旁邊寫著「You can also see the summary of teacher model」。好奇的學生把它打開，老師就被悄悄改壞了，之後拿它來蒸餾，學到的是一個比較差的老師，而且不會有任何錯誤訊息。本書已經回頭把第 0、1 章與目錄頁的老師準確率改成 0.87143。

學生也被 summary 動過：train.py 第 63 行對剛建好的學生呼叫 summary，學生第一個 BatchNorm 的 running mean 從 0 變成 −0.04 附近、running var 從 1 變成 0.90 附近。這沒有實際傷害，因為訓練開始後 running 統計量會被真實資料不斷更新；而且參照版也做了同一件事，逐位元比對照樣成立。

規則：對訓練好的模型做任何「檢查」之前，先 eval()

任何會跑 forward 的工具——torchsummary、FLOPs 計數器、匯出 ONNX、畫計算圖——在訓練模式下都可能改到 BatchNorm 的統計量（Dropout 則會讓輸出帶隨機性）。對已經訓練好的模型，先 model.eval() 再檢查；或是檢查完重新載入權重。第 2 章的 hw13_count.py 量 MACs 時都先 eval()，所以那些數字不受影響；本書的實驗工具只對學生呼叫 summary，老師在蒸餾前就 eval()，A 組的蒸餾也不受影響。

3.4　老師的機率分布：label 沒說的事

分類模型的輸出是 11 個 logits（還沒經過 softmax 的分數），softmax 之後變成 11 個加總為 1 的機率。資料的 label 只說「這張是蛋」，等於一個 one-hot 向量：蛋 100%、其他 0%。老師的機率分布卻會說「這張 85% 是蛋，但有點像麵包」。這些分給錯誤類別的小機率，Hinton 等人（2015）稱為 dark knowledge：它反映了類別之間的相似性，是 label 沒有的資訊。知識蒸餾的出發點，就是讓學生去學這個分布，而不只是學 one-hot 的 label。

這對蒸餾的意思是：如果直接用老師的機率（也就是溫度 T = 1）去教學生，學生在訓練集上看到的幾乎就是原本的 label，多學不到什麼。第 1 章看到的 A10 結果（KD 0.51720、CE 0.51545，在亂數雜訊之內）並不意外。報告第 2-1 題要求用 α = 0.5、T = 1.0 寫 loss，那正是一個幾乎沒有效果的設定。要讓 dark knowledge 浮出來，得把分布「軟化」，這就是溫度的工作。

3.6　溫度 T：把分布變軟

溫度的作法很簡單：softmax 之前，把 logits 除以 T。

p_i(T) = exp(z_i / T) / Σ_j exp(z_j / T)

T = 1 就是原本的 softmax。T > 1 時，logits 之間的差距被縮小，指數之後的差距也跟著縮小，機率就從最大的那一類往其他類「流」；T 趨近無限大時，每一類都是 1/11。T < 1 則相反，分布變得更尖。順序不會變：最大的 logit 永遠是最大的機率，所以溫度不改變預測的答案，只改變「有多確定」。

看一張訓練集的圖（3_0.jpg，蛋）。老師的 logits 是蛋 11.39、甜點 1.42、肉類 −1.20、麵食 −4.10、海鮮 −4.47……：

T = 1 時這張圖就是「蛋，99.99%」，和 label 沒有差別。T = 4 時，甜點（6.85%）、肉類（3.55%）、麵食（1.72%）、海鮮（1.57%）浮現出來：老師其實覺得這張蛋有一點像甜點、有一點像肉類。T = 8 時，蛋只剩 44.21%，排序不變，但其他類別的相對大小清楚多了。另一張圖 7_0.jpg（米飯）的 logits 是米飯 21.10、蔬果 3.27，差距大得多：T = 4 時米飯仍有 97.96%、蔬果 1.13%；要到 T = 8，蔬果才有 7.85%。每張圖需要的「軟化程度」不一樣，T 是一個全體共用的折衷。

報告第 2-2 題問：溫度 T 越高，分布是更軟還是更硬？答案是 (a)：T 越高，各類別之間的機率越平均，分布越軟（softer）。上表的熵隨 T 單調上升，就是這件事的實測。

溫度在 LLM 裡也是同一個東西

用過 ChatGPT API 的人都看過 temperature 這個參數，它做的事和這裡一模一樣：取樣下一個字之前，把 logits 除以 temperature。溫度高，機率分布軟，取樣出比較少見的字；溫度低，分布尖，幾乎總是選最可能的字（temperature 0 通常被實作成直接取最大值）。蒸餾裡的 T 是用來「讀出」老師的相似性資訊，取樣裡的 temperature 是用來控制多樣性，數學上是同一個除法。

本章重點

  • 老師是 ResNet-18：7×7 步幅 2 的卷積加 max pooling 先縮到 56×56，四個 stage 各兩個 BasicBlock（兩個 3×3 卷積加殘差連接）。助教訓練了 72,813 步，不是預訓練權重。
  • 驗證準確率 0.87143（不是 Phase 0 量到的 0.86093）。最弱的是麵包、甜點、乳製品；錯誤集中在麵包、甜點、蛋、肉類、炸物這一群。
  • 在訓練模式下對老師呼叫 torchsummary，會用隨機輸入改掉 BatchNorm 的 running 統計量，準確率掉到 0.863 或 0.861。檢查訓練好的模型之前，先 eval()。
  • 老師的機率分布在驗證集上帶著類別相似性（麵包的圖有 6.27% 給蛋），這是 label 沒有的 dark knowledge。
  • 但在訓練集上，老師準確率 0.9998、97.89% 的圖信心超過 0.99，T = 1 時其他類只分到 0.15%：T = 1 的蒸餾幾乎等於用原本的 label 訓練。
  • 溫度 T 把 logits 除以 T，不改變排序、只改變軟硬。訓練集上 T = 4 時其他類分到 14.55%、T = 8 時 47.46%；T 越高越軟（報告 2-2 選 (a)）。

自我測驗

1. ResNet-18 的卷積為什麼都設 bias=False？

每個卷積後面都緊接一個 BatchNorm。BatchNorm 會先減掉這一批的平均值，卷積的 bias 對每個位置都加同一個常數，減平均時就被抵消了；BatchNorm 自己還有一個平移參數 β，可以做 bias 能做的事。放了 bias 只是多了一些沒有作用的參數。範例學生的卷積後面也接 BatchNorm，卻保留了 bias，那 228 個 bias 參數其實是浪費的（在 100,000 的上限下，省下來可以拿去加寬別的層）。

2. 有人在蒸餾前加了一行 summary(teacher_model, (3, 224, 224), device='cpu') 想確認老師的參數量，之後才 teacher_model.eval()。蒸餾時用的老師會受影響嗎？

會。summary 執行時老師還在訓練模式，那一次 forward 已經用隨機輸入更新了每個 BatchNorm 的 running mean 與 running var；之後再 eval()，用的就是被改過的統計量。本章實測這樣的老師在驗證集上只有 0.863（原本 0.871）。要嘛先 eval() 再 summary，要嘛 summary 之後重新載入權重。

3. 老師在訓練集上的準確率是 0.9998，在驗證集上是 0.871。這代表老師過擬合了嗎？這對蒸餾是好事還是壞事？

訓練與驗證之間差了 13 個百分點，是過擬合的典型樣子（雖然驗證準確率仍然不錯）。對蒸餾來說是壞事：學生是在訓練集上向老師學的，而老師在訓練集上的輸出幾乎是 one-hot，dark knowledge 只剩 0.15%，要靠很高的 T 才能挖出來。一個在訓練集上「沒那麼有把握」的老師，例如訓練時用了較強的增強或 label smoothing，可能是更好的老師。投影片 Boss 的建議之一「make your teacher much stronger」，換個角度看也可以是「讓老師在訓練集上不要那麼死背」。這段是推論，本書沒有重新訓練老師來驗證。

4. 把 logits 除以 T = 4，會不會改變老師對驗證集的準確率？

不會。除以一個正數不改變 logits 的大小順序，softmax 又是單調的，所以最大機率的類別不變，argmax 得到的預測完全相同，準確率還是 0.87143。改變的只有機率的軟硬程度，例如驗證集的平均最大機率從 0.9418 降到 0.6999。

5. 為什麼 7_0.jpg（米飯）在 T = 4 時仍有 97.96% 是米飯，3_0.jpg（蛋）在 T = 4 時卻只剩 82.67%？

因為兩張圖的 logits 差距不同。米飯那張最大的 logit（21.10）比第二大的（3.27）多了將近 18，除以 4 之後仍差 4.5，exp(4.46) ≈ 86 倍；蛋那張最大（11.39）比第二大（1.42）只多了將近 10，除以 4 之後差 2.5，exp(2.5) ≈ 12 倍。同一個 T，對「老師很確定」的圖軟化得少，對「老師有點猶豫」的圖軟化得多。
