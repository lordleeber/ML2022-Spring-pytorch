ML2022 Spring · HW13 讀碼教材

第 0 章　全貌：一條參數上限、一個老師、一個學生

這一章先把整份作業跑一遍：規則是什麼、資料從哪來、學生和老師各長什麼樣子、指令怎麼下、跑多久、印出什麼。讀完這章，你手上會有一個 87,907 個參數、驗證準確率 0.504 的學生，以及一個 11,182,155 個參數、驗證準確率 0.871 的老師；後面八章要回答的，就是怎麼把前者往後者推近。

0.1　題目：把模型縮到 100,000 個參數以內

HW13 的主題是 network compression（模型壓縮）：讓模型變小，但盡量不要變笨（投影片 p.3：Make your model smaller without losing the performance）。任務本身沿用 HW03：把食物照片分成 11 類。不同的是這次多了一條硬規定——模型的參數總數不能超過 100,000（p.10），違反就整份作業 0 分。參數數量要用 torchsummary 這個套件來算，不可訓練的參數也要算進去；如果用好幾個模型做 ensemble（集成，把多個模型的預測合起來），所有模型的參數要加總，總和一樣不能超過 100,000（p.11）。

100,000 有多小？HW03 範例的 CNN 有 1,283 萬個參數，這份作業提供的老師模型有 1,118 萬個。上限只有它們的百分之一不到。

除了參數上限，還有幾條規則會影響你能用的手段（p.9–10）：

  • 不能用任何預訓練模型（在影像資料集上訓練過的權重），也不能用額外的資料。唯一的例外是助教提供的老師模型，你也可以自己訓練一個更強的老師。
  • 測試集只能拿來推論。投影片特別解釋原因：如果用老師模型替測試集標上 pseudo-label（偽標籤），再讓學生去擬合這些標籤，Kaggle 分數可以衝到接近老師，但這只是在測試集上過擬合，違背了壓縮的目的。
  • 一天最多上傳 5 次到 Kaggle。

評分總共 10 分（p.12）：Kaggle 的四條基準線，public 與 private 排行榜各 0.5 分，共 4 分；繳交程式碼 2 分；報告 4 分。四條基準線與投影片建議的做法（p.14–15）：

0.3　模型總覽：學生與老師

這份作業有兩個模型。學生（student）是你要訓練、要交出去的模型，受 100,000 個參數的限制；老師（teacher）是助教訓練好的大模型，只用來幫忙訓練學生，本身不交。兩個都定義在 model.py。

學生：四個卷積層加一個全連接層

範例的學生是一個很普通的 CNN：四組「卷積 → BatchNorm → ReLU」，中間穿插三次 2×2 的 max pooling，最後用 global average pooling（全域平均池化：每個通道整張特徵圖取一個平均值）把空間維度壓成 1×1，再接一個全連接層輸出 11 類的分數。

幾個要注意的地方：

  • 四個 nn.Conv2d 的 kernel 都是 3、沒有指定 padding，所以是 padding 0：224 經過一個 3×3 卷積變 222，再一個變 220。nn.MaxPool2d(2, 2, 0) 是 2×2、步幅 2 的池化，邊長減半（220 → 110）。
  • 第 45 行的 nn.AdaptiveAvgPool2d((1, 1)) 不管輸入多大都輸出 1×1，所以全連接層只要接 100 個數（註解說的 for various input size）。這是控制參數量的關鍵：如果像 HW03 範例那樣把特徵圖直接攤平接全連接層，100×26×26 = 67,600 個數接到 11 類就要 74 萬個參數。
  • 第 56–58 行的 get_student_model() 是作業規定的介面：助教會直接呼叫它來取得你的學生、算參數量，所以它不能有參數。報告第 1 題要把整個區塊（包括這個函式）貼上去。
  • 第 22 行的 TODO（Modify your model architecture）是給你改架構用的，第 5 章會換成 depthwise／pointwise 卷積。

參數量手算一遍（卷積的參數是「輸出通道 × 輸入通道 × 3 × 3 個權重，再加每個輸出通道一個 bias」；BatchNorm 每個通道有一個縮放 γ 和一個平移 β）：

老師：ResNet-18

老師是 torchvision 內建的 ResNet-18，只把最後一層改成輸出 11 類。助教訓練好之後存成 resnet18_teacher.ckpt，notebook 的註解說它在測試集上的準確率約 89.9%。

第 68 行先建一個隨機初始化的 ResNet-18，第 71 行再把助教的權重載進去。原版 notebook 這裡寫的是 torch.hub.load('pytorch/vision:v0.10.0', 'resnet18', pretrained=False, num_classes=11)，執行時會從 GitHub 下載 torchvision 0.10.0 的原始碼；本 repo 改用已經安裝的 torchvision 建同一個架構，第 1 章會說明這個改動，以及為什麼它必須留在 train.py 裡原本的位置。ResNet-18 的結構（殘差連接、四個 stage）在第 3 章細讀，這裡先看規模：

老師的參數是學生的 127 倍，存成檔案是 123 倍（44,806,605 bytes 對 363,645 bytes，檔案裡除了參數還有 BatchNorm 的統計量）。兩者的設計思路也不同：老師一開始就用步幅 2 的 7×7 卷積加 max pooling，把 224 縮到 56 才開始堆疊卷積；學生則在 222×222 的全解析度上連做兩層卷積。這個差別不影響參數量，卻嚴重影響計算量，第 2 章會量給你看。

在本機的驗證集上，老師的準確率是 0.87143（3,430 張答對 2,989 張），比註解說的 0.899 低了將近 3 個百分點。0.899 是 Kaggle 測試集的數字，本機無從驗證；第 3 章會看老師在哪些類別上出錯，並說明一個讓老師在不知不覺中變笨的陷阱：在訓練模式下對它呼叫 torchsummary。

Simple 的設定是 cross entropy（'CE'）、10 個 epoch。patience 300 表示連續 300 個 epoch 沒進步才提早停，總共才 10 個 epoch，等於不會提早停。exp_name 決定輸出資料夾：每次實驗換一個名字，才不會蓋掉上一次的權重。train.py 也接受 --exp_name、--loss_fn_type、--n_epochs 三個選項，覆蓋 cfg 裡的同名設定（第 1 章）。

三件事值得先記住：

  • 還沒學完。訓練準確率只有 0.515，和驗證準確率差不多，loss 還在穩定下降：這是欠擬合（underfitting），不是過擬合。模型太小、訓練太短，兩者都可能是原因。投影片 Medium 的建議之一就是「訓練更久」，第 4 章的 50 個 epoch 實驗會回答「光是訓練更久能到哪裡」。

0.6　notebook 拆成哪些檔

原版是一份 32 格的 notebook。本 repo 把它拆成六個檔（目錄頁有對照表）：config.py、dataset.py、model.py、kd.py、train.py、test.py。改動只有三處：補上 kd.py 的 TODO（第 4 章）、老師改從本機的 torchvision 建（第 1 章）、Medium 的開關從「手動取消註解」改成 --loss_fn_type KD（第 1 章）。

拆完之後怎麼確定沒有改變結果？做法和前幾本書一樣：把 notebook 的程式格原樣串成一支「參照」腳本（只註解掉 !wget、!tar 兩行 shell 指令，並換掉 torch.hub.load），跑一次；再跑拆好的 train.py 與 test.py，比對三樣東西：印出的每一行、存下的學生權重（每一個張量用 torch.equal 比）、submission.csv（逐位元組比）。三樣全部相同。產生參照腳本的工具是 docs/tools/hw13_make_ref.py，第 1 章會細講這個過程，以及拆檔時最容易踩到的一個坑：建一個暫時用不到的模型，也會改變結果。

  • 範例學生：四個 3×3 卷積（3→32→32→64→100）加全域平均池化與 Linear(100, 11)，87,907 個參數，最後一個卷積佔 66%。老師：ResNet-18，11,182,155 個參數（127 倍），layer4 佔 75%；驗證準確率 0.87143，低於宣稱的 0.899（測試集）。

自我測驗

1. 把學生最後一個卷積從 nn.Conv2d(64, 100, 3) 改成 nn.Conv2d(64, 128, 3)（BatchNorm 與 Linear 跟著改成 128），參數總數會不會超過 100,000？

會。卷積變成 128·64·9 + 128 = 73,856，BatchNorm 變成 256，Linear 變成 11·128 + 11 = 1,419。其他層不變（896 + 9,248 + 18,496 + 64 + 64 + 128 = 28,896），合計 28,896 + 73,856 + 256 + 1,419 = 104,427，超過 100,000。這是手算，沒有實際跑；用 sum(p.numel() for p in model.parameters()) 就能驗證。

2. 如果拿掉 nn.AdaptiveAvgPool2d((1, 1))，把最後的特徵圖直接攤平接 nn.Linear，這一層要多少參數？

最後一個 pooling 之後是 (100, 26, 26)，攤平是 67,600 個數；接到 11 類需要 67,600·11 + 11 = 743,611 個參數，光這一層就超過上限 7 倍。全域平均池化把每個通道壓成一個數，全連接層只剩 1,111 個參數，這是小模型常用的省參數手段。

3. HW13 的訓練與驗證資料和 HW03 完全相同。那麼直接拿 HW03 訓練好的 submission.csv 來交，會發生什麼事？

分數會接近亂猜。測試集的照片雖然相同，但檔名被打亂重新編號（HW13 的 0000.jpg 是 HW03 的 0095.jpg），submission.csv 是照 Id 對答案的，順序錯了，預測就對到別張照片上。何況 HW03 的模型多半超過 100,000 個參數，本來就不能交。

4. Simple 的訓練準確率（0.515）和驗證準確率（0.502）幾乎一樣。這代表模型「沒有過擬合，所以已經夠好了」嗎？

不代表。兩者接近只說明沒有過擬合；兩者都低、loss 還在下降，代表的是欠擬合：模型還沒學會訓練資料本身。改善的方向是讓模型學得更多（訓練更久、更好的架構、更有資訊量的訓練目標，例如老師的輸出分布），而不是加正則化。

5. 老師的參數是學生的 127 倍，檔案大小卻只有 123 倍。差在哪裡？

檔案裡除了參數，還存了 BatchNorm 的 running mean、running var（每個通道各一個數）與 num_batches_tracked，以及 PyTorch 序列化格式本身的額外資料。學生的 BatchNorm 通道（228 個）相對於它的參數量，比例比老師的高，所以這部分的額外負擔在學生身上佔得比較多，比值就比 127 小。第 2 章會把檔案裡的每一類東西列出來。
