第 4 章　EWC：用 Fisher 資訊衡量重要度

Elastic Weight Consolidation 是這類方法的原型：學完一個任務，估計每個參數對它有多重要，之後用一條「彈簧」把重要的參數拉在原位。第 0 章的成績表裡，EWC 和 baseline 幾乎一樣。這一章讀它的程式，找出原因：程式算出的重要度比論文的定義小了一百多倍，λ = 100 根本拉不住；舊任務的重要度還被重複累加。把 λ 調到 10,000，EWC 才開始有作用。

4.1　想法：把舊任務的 loss 近似成一個二次碗

假設模型學完任務 A，停在權重 θ*A。現在要學任務 B，同時希望任務 A 的 loss 不要變大。最直接的做法是同時最小化兩個任務的 loss，但我們已經看不到任務 A 的資料了。EWC 的辦法是把任務 A 的 loss 在 θ*A 附近用一個二次函數近似：θ*A 是任務 A 的最低點，一階項（梯度）大約是 0，剩下的就是二次項，由 loss 的曲率決定。某個參數方向上曲率大，代表沿著它稍微移動，任務 A 的 loss 就上升很多，這個參數就重要；曲率小的方向可以隨便動。

曲率要用 Hessian（二階導數矩陣）來算，對 146 萬個參數的模型來說，那是一個 146 萬 × 146 萬的矩陣，算不出來也存不下。EWC 用兩個近似把它變得可行：

  • 用 Fisher 資訊矩陣取代 Hessian。對「負的 log-likelihood」這種 loss，在最佳點附近，Fisher 矩陣等於 Hessian 的期望值，而 Fisher 只需要一階梯度就能算：它是「log-likelihood 的梯度」的外積的期望值。
  • 只取 Fisher 矩陣的對角線：每個參數一個數，忽略參數之間的交互作用。這樣重要度就和參數一樣大小，正好可以存成第 3 章那種「和參數同形狀的張量」。

notebook 的 EWC 說明寫的 loss 是：

LB(θ) = L(θ) + Σi (λ/2) · Fi · (θi − θ*A,i)²
F = E[ ∇log p(yn | xn, θ*A) · ∇log p(yn | xn, θ*A)T ]，只取對角線 Fi

L(θ) 是任務 B 的分類 loss，後面那一項就是第 3 章的 Σ Ω (θ − θ*)²，Ω 換成 Fisher 的對角線 Fi。從貝氏的角度看，這相當於把「學完任務 A 之後的參數分布」近似成一個以 θ*A 為中心、精確度（變異數的倒數）為 F 的常態分布，再拿它當學任務 B 時的先驗。這也是程式裡把重要度叫做 _precision_matrices 的原因。

4.2　程式：每個 batch 算一次梯度、平方、平均

分兩段讀。第 38–42 行先建一份全 0 的重要度，再把 previous_guards_list 裡每一份舊的重要度（guard，守衛：notebook 借用李宏毅老師上課的說法，指保護舊任務的那個量）加上去。4.4 節會回來看這一段。

第 45–64 行是這個任務自己的 Fisher：走過這個任務的訓練資料（469 個 batch），每個 batch：

  1. self.model.zero_grad() 清掉上一個 batch 的梯度。
  2. forward，算 F.nll_loss(F.log_softmax(output, dim=1), label)。log_softmax 之後接 nll_loss，就等於 cross_entropy：這正是負的 log-likelihood −log p(y | x, θ)，對 batch 取平均。
  3. backward()，然後把每個參數的梯度平方，除以 batch 數 469，累加進去。

469 個 batch 跑完，重要度就是「每個 batch 的平均 NLL 梯度的平方」的平均。它用的是資料的真實 label（第 55 行的註解：Simply use ground truth label of dataset）。投影片 p.19 問「這個方法需不需要 label」，從這一行看答案是需要。

第 44 行的 model.eval() 對這個沒有 Dropout／BatchNorm 的模型沒有作用；它也不會影響之後的訓練，因為下一次呼叫 train() 時第一行就是 model.train()（第 2 章 2.3 節）。另外，迴圈結束後最後一個 batch 的梯度仍留在參數的 .grad 裡，EWC 的 update() 不做事，train() 每一步又會先清梯度，所以沒有影響；第 6 章會看到 SI 對這種「殘留的 .grad」是敏感的。

λ 設在第 75 行：lll_lambda=100。公式裡的 1/2 在程式中沒有出現，等於把 λ/2 整個寫成 λ，只差一個常數倍，調 λ 時一併吸收即可。

4.3　先平均再平方：小了一百多倍

公式裡的 F 是每一筆資料的梯度外積的期望值：先對每張圖各自算梯度、各自平方，再平均。程式是先對一個 batch 的 128 張圖平均 loss（等於平均梯度），再平方。兩者不一樣：

程式：　( (1/B) Σk gk )² = (1/B²) Σk gk² + (1/B²) Σk≠l gk gl
公式：　(1/B) Σk gk²

gk 是第 k 張圖對某個參數的梯度，B = 128。模型在任務 A 上訓練好之後，不同圖片的梯度方向大致互相抵消（整體的平均梯度接近 0），交叉項 Σ gk gl 很小，程式算出的值就大約是公式的 1/B。

本書用 docs/tools/hw14_fisher.py 實際量了一次：只在任務 1 上訓練一個模型（10 個 epoch，和作業相同的設定），然後在任務 1 的 60,000 張訓練圖上用三種方法算 Fisher 對角線。逐樣本的梯度用 torch.func 的 vmap 一次算一整個 batch：

算法全部參數的總和最大值fc1fc2fc3fc4
程式的做法：batch 平均 NLL 的梯度平方0.4534.83e-40.2100.0310.0360.175
empirical Fisher：每張圖的梯度平方（真實 label）50.140.053624.193.383.8718.70
true Fisher：每張圖的梯度平方（label 從模型自己的預測抽）90.820.096845.066.056.7432.97

empirical Fisher 是程式算法的 110.7 倍，接近 B = 128（交叉項不完全是 0，所以比 128 小一點）。但兩者在 146 萬個參數上的 Pearson 相關係數是 0.996，排序的相關係數（Spearman）是 0.999：哪個參數比較重要，兩種算法幾乎完全同意，只是整體大小差了約 111 倍。所以這不是「算錯了重要度」，而是「重要度的單位不同」：程式的 λ = 100，相當於論文算法下的 λ ≈ 0.9。這解釋了第 0 章 EWC 與 baseline 幾乎一樣的原因，也是第 0 章提到「EWC 重要度加總只有 0.44」的由來。

true Fisher 是另一種常見的定義：label 不用資料的真實值，而是從模型自己預測的機率分布抽樣。它和 empirical Fisher 的相關係數是 0.987，總和大 1.8 倍（模型在訓練資料上非常有把握，抽到的 label 有時和真實的不同，那些樣本的梯度大）。用 true Fisher 時不需要 label，所以投影片「需不需要 label」的問題，嚴格說答案取決於用哪一種定義；這份程式用的是真實 label。

4.4　舊任務的重要度被重複累加

回到 4.2 節的兩段程式。run_ewc 每個任務結束時把目前這個物件的 _precision_matrices append 進 prev_guards，然後建新物件；新物件在第 38–42 行把 prev_guards 裡的每一份都加起來，再加上新任務的 Fisher。問題在於，目前這個物件的 _precision_matrices 本身已經是「前面所有 guard 加上它自己那個任務的 Fisher」。用 Fk 表示任務 k 自己的 Fisher，推一次：

學完prev_guards 的內容新物件的重要度
任務 1[0]（第一個物件，dataloader=None）F1
任務 2[0, F1]F1 + F2
任務 3[0, F1, F1+F2]2F1 + F2 + F3
任務 4[0, F1, F1+F2, 2F1+F2+F3]4F1 + 2F2 + F3 + F4

任務 1 的權重每多一個任務就加倍。原本的意思應該是「每個任務的 Fisher 各算一次、加總」（F1 + F2 + F3 + F4）。要修正，只要把 prev_guards 改成只放最新那一份：prev_guards = [lll_object._precision_matrices]。本書的實驗工具用 --guards latest 做了這個修正（C 組），兩者的重要度總和（種子 0，各自獨立跑）可以直接對照：

學完任務 1任務 2任務 3任務 4
原版（重複累加）0.5060.8371.7033.228
只算一次（C 組）0.5060.8371.1971.326

前兩個任務完全相同（推導表裡兩種寫法在任務 2 之前沒有差別），從任務 3 開始原版變大。數字也對得起來：任務 3 自己的 Fisher 是 1.197 − 0.837 = 0.360，原版是 0.506 + 0.837 + 0.360 = 1.703，正好多算了一份 F1 + F2。

但修正之後結果幾乎沒變：ACC 71.29（原版 71.67），BWT −33.46（原版 −32.93）。理由在 4.3 節：重要度本身太小，乘上 λ = 100 後懲罰項微不足道，加倍與否都拉不住參數。這個 bug 在 λ 夠大的時候才會有影響，第 8 章會在其他方法上再看一次。

4.5　把 λ 調大

B 組實驗把 EWC 的 λ 從 10 掃到 10,000（種子 0，每次只跑 EWC；λ = 100 那一點用 A 組種子 0）。下圖是任務 1 的準確率在 50 個 epoch 裡的變化：

λ 從 10 到 1000 幾乎沒有差別；到 10,000 時 ACC 跳到 80.75，任務 1 最後保住了 56.38。依 4.3 節的換算，程式的 λ = 10,000 大約等於逐樣本 Fisher 下的 λ ≈ 90。

代價也同時出現：對角線從 98% 一路降到 95.73。λ 越大，參數越難離開原位，新任務就學得越不好。這就是第 2 章說的穩定性與可塑性的取捨，BWT 從 −32.93 改善到 −20.47，一部分是因為真的記住了，一部分是因為新任務學得沒那麼好、可以掉的空間變小了。再往上調能不能更好、會不會開始學不會新任務，本書只掃到 10,000，沒有再往上跑；第 8 章把五種方法調過 λ 之後的最好結果放在一起比。

回到作業的設定 λ = 100：五個種子的 ACC 是 71.67、70.85、71.69、71.82、72.03，平均 71.61 ± 0.45；baseline 是 69.47 ± 1.40。EWC 確實比 baseline 好約 2 個百分點，但這個差距和 baseline 自己換種子的變動同一個量級，單看一個種子很容易誤判為「EWC 沒用」或「EWC 有用」。

4.6　EWC 要多存什麼、多算什麼

和 baseline 比，EWC 多出兩種成本，在這個小模型上感覺不到，換成大模型就是決定能不能用的因素：

  • 記憶體：每個 EWC 物件存一份重要度和一份舊權重，各和模型一樣大（1,462,538 個 float32，約 5.9 MB）。更麻煩的是 prev_guards：它是一個 list，存的是每個舊物件 _precision_matrices 的參考，舊物件被丟掉了，這些張量仍然被 list 抓著，不會釋放。學完五個任務時，list 裡有 5 份重要度，加上目前物件的一份，記憶體隨任務數線性成長。若照 4.4 節的修正只保留最新的一份，就只需要固定的兩份。一個 70 億參數的語言模型，每一份 float32 的副本就是 28 GB。
  • 計算：每個任務結束時多跑一個 epoch 的 forward 與 backward（469 個 batch）來算 Fisher；訓練時每一步多算一次懲罰項，要走過全部參數做逐元素運算。用逐樣本梯度算 Fisher（4.3 節的做法）會更貴：一個 batch 要存 128 份參數大小的梯度，這個模型是 128 × 146 萬個數，約 750 MB。

這兩點也說明了為什麼 EWC 在大模型上常被簡化：只保留一份累積的重要度（online EWC），或乾脆不估計重要度、對所有參數用同一個權重（等於 L2 懲罰）。

現在的做法：EWC 的想法還在，算法換了

EWC 的核心（用曲率估計參數的重要度，在 loss 裡加一個以舊權重為中心的二次懲罰）在 2026 年仍然常見，但實作上有幾點改變：Fisher 用逐樣本的梯度算（PyTorch 2.x 的 torch.func.vmap 讓這件事只要幾行），或用 K-FAC 這類保留層內交互作用的近似；多個任務時用 online EWC（Schwarz 等，2018）維護一份隨時間衰減的 Fisher，而不是每個任務各存一份；也有研究指出 empirical Fisher 和真正的曲率可能差很多（Kunstner 等，2019），使用時要清楚自己在近似什麼。在大型語言模型的微調裡，更常見的是更簡單的版本：直接對「離預訓練權重的距離」加 L2 懲罰（L2-SP），不估計每個參數的重要度；或者乾脆只訓練 LoRA 這類附加參數，讓原本的權重完全不動。

本章重點

  • EWC 把舊任務的 loss 在 θ* 附近近似成二次函數，曲率用 Fisher 資訊的對角線估計；懲罰項是 Σ (λ/2) Fi (θi − θ*i)²，程式省略了 1/2。
  • 程式的 Fisher：每個 batch 算平均 NLL（用真實 label）的梯度、平方、對 469 個 batch 平均。這比逐樣本的 empirical Fisher 小 110.7 倍（約 1/B），但兩者相關係數 0.996：形狀相同，大小不同。所以作業的 λ = 100 約等於論文的 λ ≈ 0.9。
  • prev_guards 存的是已經含舊 guard 的矩陣，舊任務的重要度每個任務加倍（學完任務 4：4F1 + 2F2 + F3 + F4）。實測總和 1.703 對修正後 1.197；但 λ 太小，修正後 ACC 幾乎不變（71.29 對 71.67）。
  • λ 掃描：10、100、1000 都在 72 上下；λ = 10000 時 ACC 80.75、BWT −20.47、任務 1 保住 56.38，對角線降到 95.73。
  • 作業設定下五個種子：EWC 71.61 ± 0.45，baseline 69.47 ± 1.40。

自我測驗

1. 投影片問：EWC 需不需要 label？

這份程式需要：第 59 行的 nll_loss 用的是資料的真實 label（empirical Fisher）。但 Fisher 的另一種定義（true Fisher）是從模型自己預測的分布抽 label，那樣就不需要真實 label；本章 4.3 節實測兩者的相關係數是 0.987。回答選擇題時以程式為準，並留意題目問的是哪一種定義。

2. 如果把 DataLoader 的 batch 大小從 128 改成 1 來算 EWC 的 Fisher（其他不變），重要度的總和大約會變成多少倍？λ = 100 會比較有效嗎？

batch 大小 1 時，程式的算法就變成逐樣本的 empirical Fisher；依 4.3 節的實測，總和約變成 110.7 倍。重要度變大，λ = 100 的懲罰項也跟著大約 111 倍，效果應該接近 B 組 λ = 10000 那一組。這題是推論，本書沒有用 batch 1 實際重跑 EWC（469 個 batch 會變成 60,000 次 backward）。

3. 學完任務 4 之後，原版程式中任務 1 的 Fisher 被算了幾次？修正的方法是什麼？

4 次（4F1 + 2F2 + F3 + F4）。修正：prev_guards 只放最新的那一份，例如把 prev_guards.append(...) 改成 prev_guards = [lll_object._precision_matrices]。新物件就是「前面所有任務的 Fisher 各一次」加上新任務的 Fisher。

4. 為什麼修正了重複累加，EWC 的結果幾乎沒變？

因為 λ = 100 搭配這份程式算出的 Fisher（總和不到 1），懲罰項太小，幾乎沒有拉住參數。重要度乘 2 或乘 4 仍然太小。重複累加的影響要在 λ 夠大、懲罰項真的起作用時才看得出來。

5. λ = 10000 時 BWT 改善到 −20.47。可以說 EWC 記住了更多嗎？

部分可以：任務 1 最後從 35.54 升到 56.38，確實保住更多。但對角線也從約 98% 降到 95.73，新任務學得比較差，BWT 的「最後 − 剛學完」中，「剛學完」那一項變小了，也會讓 BWT 看起來比較好。所以要同時看 ACC（80.75，也明顯提高）和對角線，才能說「記住更多，代價是新任務略差」。

  • Jonathan Schwarz 等，Progress & Compress: A scalable framework for continual learning（2018）：online EWC。
