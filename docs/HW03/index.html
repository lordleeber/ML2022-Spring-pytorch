ML2022 Spring · HW03 讀碼教材

HW03　食物影像分類：從零訓練一個 CNN

給你一張食物照片，猜它屬於 11 類裡的哪一類：麵包、甜點、湯、海鮮……。作業規定不准用預訓練模型，所以卷積神經網路（CNN）要從隨機的權重開始，只靠 9,866 張訓練照片學起來。書中每一段程式碼都逐字取自本 repo，每一個數字都是在本機實際跑出來的。

先說在前面：用現在的眼光讀 2022 年的作業

這份作業出自 2022 年春季的課程。原版是一份 notebook，投影片強烈建議在 Kaggle 的 GPU 上執行；助教附了一份能跑、但只到最低基準線的範例程式（sample code）。本 repo 把它拆成六個 .py 檔，只改了少數幾個設定，2026 年在本機用當下的套件版本重新跑過一遍。動手之前，先分四個層次把差異講清楚。

第一層：環境——notebook 拆成六個檔，改了一行才跑得起來

原版用 ! wget 從 Dropbox 下載 food11.zip、! unzip 解壓縮，這是 notebook 專屬的寫法（開頭的 ! 代表「交給 shell 執行」），在本機用不上，資料改成事先從 Kaggle 下載、解壓縮到 HW03/food11/。一份 notebook 拆成六個檔：

套件方面，有一行非改不可：原版從檔名取標籤時寫 fname.split("/")，本 repo 曾改成 Windows 的 "\\"，在 Linux 上又會壞掉，commit 381aad0 把它改成跨平台的 os.path.basename（第 1 章會實測寫錯時每一張圖會拿到什麼標籤）。其餘部分，2026 年的 PyTorch 2.11、torchvision 0.26 跑起來都不必再改。train.py 和 test.py 把裝置寫死成 "cuda"，需要一張 NVIDIA 顯示卡才跑得起來；這是本 repo 刻意的寫法，第 0 章會說明執行環境。

第二層：本 repo 的改動——只動了設定

和 HW01、HW02 不同，本 repo 的 HW03 沒有改模型、沒有加資料增強，就是範例程式拆檔之後的樣子，只調了 batch 大小與 epoch 數。所以它的分數就是範例程式的分數，往上爬的方法（投影片列了一長串）全部留給讀者，本書在第 6–8 章實際做一遍。

0.555 高於投影片的 simple baseline 0.50099、低於 medium baseline 0.73207。這裡要先講清楚：這是本機驗證集上的準確率，不是 Kaggle 的分數。repo 裡沒有上傳 Kaggle 的紀錄，所以本書只會說它「在驗證集上落在哪兩條基準線之間」，不會說它通過了哪一條。

讀程式時還會碰到幾個「程式寫的和它看起來在做的不一樣」的地方，例如 train.py 每個 epoch 都打開 sample_log.txt 準備寫 log，跑完卻是 0 bytes。完整的清單在教學大綱，每一項都會在對應章節用實測說明。

第三層：方法——從零訓練是 2022 年作業的限制

作業規則明寫：不准用預訓練模型（pretrained model），也不准用外部資料。所以這份作業的所有技巧——資料增強、殘差連接、訓練更久、交叉驗證、ensemble——都是在「只有一萬張圖、權重從亂數開始」的前提下榨出準確率。投影片 p.33 的提醒也是同一件事：在 ImageNet 上表現最好的大模型，沒有預訓練權重時不一定好用。

現在的做法：從預訓練模型微調

今天做一個一萬張圖的分類任務，幾乎不會從零訓練。常見的起點是拿一個在大量影像上預訓練過的模型——ConvNeXt、Vision Transformer（ViT）、或 CLIP、DINOv2 這類自監督／圖文對比學習的影像編碼器——換掉最後一層、在自己的資料上微調（fine-tune），甚至只訓練最後一層。timm 與 torchvision.models 一行就能載入這些權重。投影片 p.4 自己也說「pretraining is very effective」，只是比賽期間不准用。工程上也有幾個新習慣：torchvision 的 transforms.v2 取代了這份程式用的舊 transforms；RandAugment、TrivialAugmentWide 這類自動組合的增強策略取代手調；訓練時開混合精度（torch.autocast）；DataLoader 用多個 worker 平行解碼圖片。這些在書中遇到時會用「現在的做法」框指出來。

第四層：觀念——沒有過時，這是本書的主體

卷積、池化、BatchNorm 的形狀與參數怎麼算；為什麼資料增強只用在訓練；殘差連接為什麼要形狀相同才能相加；train 與 eval 模式的差別；固定亂數種子為什麼能讓結果逐位元組重現（以及一個進度條怎麼悄悄改變了亂數順序）；怎麼確認印出來的驗證指標是不是真的；在同一個規格下公平地比較改良——這些在今天一模一樣。本書花最多篇幅的就是這一層。

這本教材在教什麼

這是台大李宏毅老師《機器學習 2022 Spring》第三份作業（HW03）的讀碼教材。HW03 的題目是 image classification（影像分類），資料來自 food-11 資料集：訓練 9,866 張、驗證 3,430 張、測試 3,347 張，分成 11 類。整條流程如下：

你會學到

JPEG 怎麼變成 0–1 的 tensor；Conv2d、BatchNorm2d、MaxPool2d 的形狀與參數怎麼算；感受野；資料增強與 test time augmentation；殘差連接怎麼接；怎麼確認印出來的驗證準確率是真的。

你會看到

只把 DataLoader 包進 tqdm 進度條，打亂的順序就變了——因為 tqdm.auto 會先偷偷呼叫一次 iter()，多抽一次亂數。還有一個每個 epoch 都被打開、卻永遠是空的 log 檔。

你會帶走

一份在同一規格下並排比較的實驗表（原版、資料增強、殘差網路、重切 train/val、label smoothing、TTA、ensemble），報告兩題的實作與實測，以及入門／進階／挑戰三級題庫。

預備知識

  • Python：會寫函式與 class，看得懂 list comprehension、f-string 與 try／except。
  • PyTorch 基礎：tensor 與它的形狀（shape）、nn.Module、forward、loss.backward()、優化器的 step()、Dataset 與 DataLoader。沒碰過的話，建議先讀同一個 repo 的 HW01 讀碼教材，那本從零講起；HW02 讀碼教材講過分類問題的 cross entropy 與準確率。
  • 分類問題：知道模型對每一類輸出一個分數、用 cross entropy 當 loss、用「答對的比例」當準確率就夠了。
  • 不需要：不需要事先懂卷積或影像處理，第 2、3 章從像素講起。也不需要 Kaggle 帳號，本書全部在本機跑。

章節目錄

  1. 第 0 章　任務、環境與模型總覽

    作業要做什麼、規則與 Kaggle 四條基準線；模型總覽（5 個卷積區塊、每一層的形狀、12,833,803 個參數手算與 PyTorch 一致）；train.py、test.py 怎麼跑、印出的每一行是什麼、跑多久。

  2. 第 1 章　解剖 food11

    三個資料夾、檔名就是標籤；11 類有多不平均（最少 280 張、最多 1,500 張）；圖片尺寸；每類一張縮圖；測試集的標籤怎麼變成 -1。

  3. 第 2 章　Transform 與 DataLoader

    Resize 把長方形壓成正方形；ToTensor 做了哪三件事；一個 epoch 39 個 batch；圖片解碼占了多少訓練時間。

  4. 第 3 章　CNN 逐行：卷積、BatchNorm、池化

    形狀公式與參數公式；BatchNorm 在 train 與 eval 時做的事不一樣；感受野從 3 長到 94；65% 的參數在第一層全連接。

  5. 第 4 章　訓練迴圈與驗證

    亂數種子與 cuDNN 決定性；梯度裁剪；被打亂的驗證集與「平均再平均」的準確率；永遠是空的 log 檔；進度條改變了亂數順序。

  6. 第 5 章　預測與 submission.csv

    3,347 張測試圖；pad4 補零；為什麼排序後的檔名剛好對得上 Id。

  7. 第 6 章　報告題 Q1：資料增強

    torchvision 常用的隨機轉換；同一張圖增強 5 次的真實結果；增強為什麼只用在訓練；mixup 與 TTA 的原理。

  8. 第 7 章　報告題 Q2：殘差連接

    照投影片的圖補完 forward；哪幾層能直接相加；一個 6,826 萬參數、其中 6,711 萬在第一層全連接的模型。

  9. 第 8 章　往上爬：改良實驗與三級題庫

    同一套規格（40 個 epoch）下並排比較各種改良；TTA 與 ensemble；一次 200 個 epoch 的長跑；入門／進階／挑戰三級題庫。

  10. 附錄　名詞對照與速查

    中英名詞對照、指令速查、每一層的 tensor 形狀、關鍵數字一覽，以及讀程式時整理出的 repo 問題清單。

學習路徑

建議照章節順序讀，順序就是一張圖片在程式裡走的路：第 0 章先讓程式跑起來、看一眼模型；第 1 章看資料長什麼樣；第 2 章看圖片怎麼變成 tensor、切成 batch；第 3 章拆模型；第 4 章看訓練與評估；第 5 章輸出答案；第 6、7 章做報告的兩題；第 8 章把各種改良放在同一張表上比較。只想知道「怎麼把分數往上推」的讀者，可以讀完第 0 章直接跳第 6 章，再回頭查需要的細節。

全書的圖都用同一套配色，顏色代表「這一步在處理什麼」：

資料（圖片、檔案、tensor） 前處理（transform、增強、切 batch） 模型的 forward（卷積、全連接） 標籤、loss 與評估（準確率、答案）
