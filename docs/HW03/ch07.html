第 7 章　報告題 Q2：殘差連接

報告的第二題給了一個 6 層卷積的 Residual_Network，要你只改 forward，照投影片的圖加上殘差連接。本章先讀懂這個模型的形狀與參數，寫出答案，再用實際訓練看它的表現——結果出乎意料：它比範例的 Classifier 差了將近 9 個百分點，而原因不在殘差，在它那個有 6,711 萬個參數的全連接層。

7.1　others.py：一份不能執行的模板

others.py 是原版 notebook 最後兩格的照抄（第 6 章 6.1 節）。第 1–14 行是 Q1 的 train_tfm，第 16–97 行是 Q2 的模型。它從頭到尾沒有 import torchvision.transforms，第 9 行一用到 transforms 就會出錯。本書實測把整個檔案交給 Python 執行：

NameError: name 'transforms' is not defined

在 notebook 裡這不是問題，因為前面幾格早就 import 過了；拆成 .py 之後，這個檔案就只能當「題目」看。本 repo 沒有任何程式 import 它，train.py 用的仍是 classifier.py 的 Classifier。本書要訓練這個模型時，是把第 22 行（from torch import nn）以後的部分單獨拿出來執行（docs/tools/hw03_exp.py 的 --arch res／res0）。

7.2　Residual_Network 的六層

六個「卷積 + BatchNorm」，裡面沒有 ReLU、也沒有池化：ReLU 是第 61 行單獨的一個 self.relu，留給 forward 自己決定放在哪裡（因為殘差要在 ReLU 之前相加，7.3 節）。縮小圖片的工作交給 cnn_layer3 與 cnn_layer5 的 stride=2（第 40、49 行的第四個參數）：第 3 章 3.2 節的公式 ⌊(128 + 2 − 3) ÷ 2⌋ + 1 = 64。本書逐層實測一張圖的輸出形狀與參數：

全部 68,259,147 個參數，是 Classifier（12,833,803）的 5.3 倍。六層卷積加起來只有 1,147,200 個，剩下的 98.3% 全在 fc_layer：最後的特徵圖是 256 × 32 × 32 = 262,144 個數字（第 57 行的 256 * 32 * 32），第一層全連接把它接到 256 個輸出，就是 262,144 × 256 + 256 = 67,109,120 個參數。Classifier 經過 5 次池化、攤平後只有 8,192 維；這裡只縮小了兩次，攤平後大了 32 倍。存下來的 checkpoint 是 273,056,689 bytes，也是 sample_best.ckpt 的 5.3 倍。

7.3　照圖接上殘差：只改 forward

先看題目給的 forward：

一條直線：每一層的輸出過 ReLU，當作下一層的輸入；第 93 行攤平（flatten(1) 和第 3 章的 view(B, -1) 效果相同），第 96 行接全連接。每兩行之間空一行，是刻意留給學生插入程式的位置。

投影片第 39 頁的圖是這樣接的：cnn_layer1 → ReLU → cnn_layer2 → ⊕ → ReLU → cnn_layer3 → ReLU → cnn_layer4 → ⊕ → ReLU → cnn_layer5 → ReLU → cnn_layer6 → ⊕ → ReLU → fc_layer。每一個 ⊕ 都從「前一個 ReLU 的輸出」拉一條線過來相加。對照 7.2 節的表：三個 ⊕ 剛好接在 cnn_layer2、cnn_layer4、cnn_layer6 後面，正是那三個「輸入和輸出形狀相同」的層——相加要求兩個 tensor 形狀完全一樣，所以殘差只能跨過不改變形狀的層。

寫成程式，只要在三個地方把「前一個 ReLU 的輸出」加回來，其餘不動：

    def forward(self, x):
        x1 = self.relu(self.cnn_layer1(x))
        x2 = self.relu(self.cnn_layer2(x1) + x1)
        x3 = self.relu(self.cnn_layer3(x2))
        x4 = self.relu(self.cnn_layer4(x3) + x3)
        x5 = self.relu(self.cnn_layer5(x4))
        x6 = self.relu(self.cnn_layer6(x5) + x5)
        return self.fc_layer(x6.flatten(1))

這就是本書的 Q2 答案（hw03_exp.py 的 --arch res 用的就是這段）。__init__ 一行都沒改，參數量也完全相同，符合「只改 forward」的規定。關鍵在「先加、再 ReLU」：self.cnn_layer2(x1) + x1 加完才過 self.relu，順序和 ResNet 論文的基本區塊一致。

殘差為什麼有用

一般的層學的是「輸入 → 輸出」的整個轉換 H(x)。加了殘差之後，這一層只需要學「輸出比輸入多了什麼」：F(x) = H(x) − x，輸出是 F(x) + x。兩個好處：如果某一層其實不需要做什麼，它只要把 F 學成 0 就好，比學成「恆等轉換」容易得多；反向傳播時，梯度可以沿著那條相加的捷徑直接傳回前面的層，不必每一層都乘一次權重，所以很深的網路也訓練得動。ResNet（2015）就是靠這個把網路疊到 152 層。

反過來說，殘差解決的是「深」的問題。這個模型只有 6 層卷積，本來就不深；7.4 節會看到，它真正的問題在別的地方。

形狀不同的層怎麼跨

題目只要求在形狀相同的地方相加。如果想讓殘差也跨過 cnn_layer3（64 → 128 通道、128 → 64 邊長），捷徑那一側要先用一個 nn.Conv2d(64, 128, 1, 2)（1×1 卷積、stride 2）把 x2 轉成同樣的形狀，ResNet 論文叫它 projection shortcut。但這需要在 __init__ 加新的層，違反這一題「只改 forward」的規定。

7.4　實際訓練：殘差網路反而比較差

第 8 章用同一套規格訓練了三個模型：都用第 6 章的增強 A、都跑 40 個 epoch，其他設定和 train.py 相同。為了單獨看殘差本身的效果，本書另外多跑了一組「Residual_Network 原樣、不加殘差」（--arch res0）。驗證欄都是整個驗證集一次算的真實值：

Classifier（augA40）12,833,803350.69050／0.688052.056140.8346039.7 秒
Residual_Network + 殘差（res40）68,259,147350.59754／0.5988319.258140.6387546.6 秒

兩個結論。第一，三個模型裡 Classifier 最好，同一個 Residual_Network 不管有沒有殘差都比它差。第二，也是比較意外的：在這個模型上，加了殘差反而變差——不加殘差的版本最佳 0.64606，加了之後是 0.59883，低了 4.7 個百分點。（每一組都只用一個亂數種子跑了一次，差距的一部分可能來自隨機性；但兩者的訓練曲線從第 1 個 epoch 起就分開了，下面會看到原因。）

和 Classifier 比，有殘差的版本差了將近 9 個百分點。看它的曲線（res40，真實值）：

這不是過擬合——過擬合是訓練很好、驗證很差。這裡訓練準確率本身就很低：40 個 epoch 之後只有 0.64，而同樣有增強的 Classifier 是 0.83。驗證準確率一路還在上升，模型是學得太慢（欠擬合，underfitting）。最可疑的是第 1 個 epoch 的平均訓練 loss 19.26：11 類的分類，什麼都不會的模型 loss 也只有 ln 11 ≈ 2.4，19 代表模型在第 1 個 epoch 裡給出了非常極端、而且是錯的預測。

原因：262,144 維輸入的全連接層 × Adam

本書用 32 張訓練圖，在 CPU 上比較三個模型剛初始化時（種子相同、train 模式、還沒更新）的狀況：

模型初始 losslogits 的標準差梯度長度（裁剪前）攤平後特徵的長度（每張圖的 L2）
Classifier2.4170.1054.82100.6（8,192 維）
Residual_Network 原樣2.4980.17229.55—
Residual_Network + 殘差2.5280.26348.90543.3（262,144 維）

初始的 loss 三者都正常（約 ln 11）。差別在梯度：殘差網路的梯度長度是 48.90，遠超過 train.py 的 max_norm=10，第一步就會被裁剪；Classifier 只有 4.82。但裁剪只能限制梯度的大小，限制不了 Adam 的步伐。Adam 把每個參數的梯度除以它自己的「梯度大小的移動平均」（第 4 章 4.3 節），所以訓練初期，每一個權重每一步都大約走 lr = 0.0003 那麼遠，和梯度本身有多大幾乎無關。第一步更是精確：Adam 的第一步，每個權重剛好移動 lr、方向是它的梯度的正負號（偏差修正後梯度除以自己的絕對值；這裡忽略很小的 eps 與 weight decay）。

對一個輸入有 n 維的全連接層，如果每個權重都往「讓 loss 下降」的方向移動 0.0003，一個輸出的變化量大約是 0.0003 × (所有輸入的絕對值總和)。Classifier 的 fc 第 1 層有 8,192 個輸入、平均值約 0.86，一步大約讓輸出變動 0.0003 × 8,192 × 0.86 ≈ 2；殘差網路的 fc 第 1 層有 262,144 個輸入、平均值約 0.65，一步大約是 0.0003 × 262,144 × 0.65 ≈ 51。一步就讓 logits 跳了幾十，模型立刻變得極端而自信，loss 也就飆到十幾、二十。（這是數量級的估算，不是實測每一步的變化；本書實測了第 1 個 epoch 的平均 loss 與初始的梯度長度，兩者都和這個估算一致：沒有殘差的版本梯度比較小，第 1 個 epoch 的 loss 也比較低。）

第 1 步三者的 loss 都是 2.4 左右（剛初始化）。只更新了一次，第 2 步的 loss 就從 2.4 跳到 25.5（原樣）與 50.5（加殘差），Classifier 則幾乎不動（2.54）。梯度長度也跟著暴增到幾百，每一步都被 max_norm=10 裁剪，但如上所說，裁剪擋不住 Adam 的步伐。加了殘差的版本初始梯度比較大（48.90 對 29.55），第一步跳得更遠、回來得更慢：10 步之後原樣的 loss 已經降到 9.96，加殘差的還在 34。這個開局的差距，一路延續成 40 個 epoch 後 4.7 個百分點的落差。

所以這個模型的問題，在於 fc_layer 第一層「262,144 維輸入 × 256 輸出」的設計，搭配一個為小模型調的學習率。殘差讓初始梯度更大（從 29.55 變 48.90），第一步就更極端，所以在這個模型上，加殘差反而變差。常見的修法不是動殘差，而是在攤平前加池化（例如 nn.AdaptiveAvgPool2d(1)，第 3 章 3.6 節的「現在的做法」，攤平後只剩 256 維），或把學習率調小、加暖身（warmup）。這些都要改 __init__ 或訓練設定，超出 Q2 的範圍；本書沒有實際訓練這些修法。

報告題要的是什麼

Q2 的評分只看「forward 有沒有照圖接對」，不看這個模型訓練起來好不好。助教選這個結構，是因為它讓殘差的位置一目了然（形狀相同的三層），不是為了拿高分。要往 Strong 以上爬，投影片第 33 頁的建議是「有下採樣（downsampling）的結構比較好」、「有了增強就別怕把模型放大」——放大的應該是卷積部分，不是全連接層。

本章重點

  • others.py 沒有 import transforms，整份執行會 NameError；沒有程式 import 它，它只是報告兩題的題目。
  • Residual_Network：6 層「Conv + BN」（ReLU 留給 forward），用兩次 stride 2 縮小；cnn_layer2、4、6 的輸入輸出形狀相同。共 68,259,147 個參數，98.3% 在 fc_layer（262,144 → 256 這一層就有 67,109,120 個）。
  • Q2 答案：x2 = relu(layer2(x1) + x1)、x4 = relu(layer4(x3) + x3)、x6 = relu(layer6(x5) + x5)，先加再 ReLU，只改 forward。殘差只能跨過形狀不變的層；跨形狀要 1×1 卷積的 projection shortcut。
  • 殘差讓每一層只學「多了什麼」、讓梯度有捷徑，解決的是「深」的問題。
  • 實測（增強 A、40 個 epoch，各一個種子）：Classifier 0.68805、Residual_Network 原樣 0.64606、加殘差 0.59883——加殘差反而變差。它是欠擬合：第 1 個 epoch 訓練 loss 19.26，40 個 epoch 後訓練準確率只有 0.64。
  • 原因：Adam 讓每個權重每步約走 lr；262,144 維輸入的全連接層一步就讓 logits 變動約 50。實測只更新一次，loss 就從 2.4 跳到 50.5（原樣 25.5，Classifier 2.54）；殘差讓初始梯度更大、第一步更極端。

自我測驗

1. 為什麼不能寫 x3 = self.relu(self.cnn_layer3(x2) + x2)？

self.cnn_layer3(x2) 是 (B, 128, 64, 64)，x2 是 (B, 64, 128, 128)，通道數與邊長都不同，相加會因為形狀無法廣播而出錯。要跨過這一層，捷徑上得先用 1×1、stride 2 的卷積把 x2 轉成 (B, 128, 64, 64)，那就要在 __init__ 新增一層。（形狀錯誤是依形狀推得的，本書沒有實際執行這一行。）

2. 把答案寫成 x2 = self.relu(self.cnn_layer2(x1)) + x1（先 ReLU 再加），還算照圖嗎？兩者有什麼差別？

不算照圖：投影片的圖是「⊕ 之後才是 ReLU」。差別在輸出的範圍：先加再 ReLU，輸出一定 ≥ 0；先 ReLU 再加，x1 本身 ≥ 0、ReLU 的結果也 ≥ 0，輸出同樣 ≥ 0，但數值會比較大，而且這一層的「殘差部分」被限制成只能往上加、不能抵銷 x1。ResNet 原始論文用的是先加再 ReLU；後來的 pre-activation ResNet 把 BN 和 ReLU 移到卷積前面，又是另一種排法。

3. 加了殘差之後，參數量變多了嗎？計算量呢？

參數量完全不變，相加沒有參數，__init__ 也沒改，仍然是 68,259,147。計算量只多了三次逐元素相加（各 64×128×128、128×64×64、256×32×32 個數字），和卷積比起來可以忽略。

4. 用 7.4 節的估算方法，如果在攤平前加一個 nn.AdaptiveAvgPool2d(1)，fc 第一層改成 nn.Linear(256, 256)，一步大約讓輸出變動多少？

攤平後只剩 256 維。假設每個平均後的數值仍是 0.65 左右，一步約 0.0003 × 256 × 0.65 ≈ 0.05，比原本的 51 小了一千倍，就不會在第一步把 logits 推到極端。fc 第一層的參數也從 67,109,120 降到 256 × 256 + 256 = 65,792。（平均值 0.65 是借用攤平前的數字，平均池化後的實際值本書沒有量；這題只是估算。）

5. 為什麼梯度裁剪（max_norm=10）救不了殘差網路的第一步？

裁剪把所有梯度等比例縮小，讓總長度不超過 10，但 Adam 接著會把每個參數的梯度除以它自己的梯度大小（的移動平均）：梯度整體縮小 5 倍，分母也跟著縮小，比值幾乎不變，每個權重的步伐仍然約等於 lr。所以對 Adam 來說，裁剪主要防的是「某一步突然暴衝、和之前差很多」的情況，不能把一開始就太大的有效步伐壓下來。要壓步伐，得調小 lr 或加 warmup。
