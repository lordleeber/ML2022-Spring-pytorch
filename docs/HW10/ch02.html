第 2 章　FGSM：對輸入取梯度，只走一步

FGSM 是整份作業最短的函式：九行程式，算一次梯度，取正負號，乘上 ε，加回去。這一章解釋為什麼「只取正負號」是 L∞ 限制下最划算的一步、為什麼這麼小的改動就能讓模型認錯（線性假說），然後實際掃一遍 ε，看白箱與黑箱的準確率怎麼變。會看到一個反直覺的結果：ε 很大時，FGSM 騙別的模型比騙自己還成功。

2.1　從訓練到攻擊：九行程式

逐行看：

  • 第 25 行：x.detach().clone() 複製一份輸入。detach 切斷它和之前計算圖的關係，clone 給它獨立的記憶體，之後改 x_adv 不會動到 x。
  • 第 26 行：requires_grad = True。訓練時 PyTorch 只追蹤權重的梯度，輸入資料預設不追蹤；這一行告訴它「這張圖也要算梯度」。
  • 第 27–28 行：前向、算 cross entropy、反向。和訓練迴圈一模一樣，差別只在之後拿的是誰的 .grad。
  • 第 30–31 行：取出輸入的梯度，grad.sign() 把每個元素變成 +1、−1（或 0），乘上 ε，加到圖片上。

和訓練相比，有兩個方向相反的地方。訓練是 w = w − lr × grad（減，讓 loss 下降），這裡是 x + ε × sign(grad)（加，讓 loss 上升），也就是梯度上升。訓練要走很多步、每步一點點；FGSM 只走一步，一口氣走到限制的邊界。名字 Fast Gradient Sign Method 就說明了這三件事：快（一步）、用梯度、只用正負號。

兩個讀程式時容易忽略的細節。第一，loss_fn 是 nn.CrossEntropyLoss()，預設對整個 batch 取平均，所以每張圖的梯度被除以了 8（batch 大小）。這不影響結果，因為正負號不會因為除以 8 改變；也因為取平均，batch 裡的每張圖互不影響——在 eval 模式下，第 2 張圖的 loss 只和第 2 張圖的輸入有關。第二，loss.backward() 不只算輸入的梯度，也會算模型所有權重的梯度，而且累加在權重的 .grad 裡，從來沒有清掉。攻擊用不到這些梯度，白白多花了記憶體與時間；比較乾淨的寫法是先 for p in model.parameters(): p.requires_grad_(False)，或改用 torch.autograd.grad(loss, x_adv) 只對輸入求導。

2.2　為什麼只取正負號

為什麼不直接加上梯度本身，而要取正負號？答案來自限制的形狀。把 loss 在原圖 x 附近用一次泰勒展開近似：

L(x + δ) ≈ L(x) + g · δ　　　g = ∇ₓL(x)，δ 是要加的雜訊

要讓 L 增加最多，就是在限制之內讓內積 g · δ = Σ gᵢ δᵢ 最大。限制是 L∞：每個 |δᵢ| ≤ ε，彼此獨立。那麼每一項各自取最大就好：gᵢ 是正的，δᵢ 取 +ε；是負的，取 −ε。這正是 δ = ε · sign(g)，這時 g · δ = ε · Σ|gᵢ| = ε ‖g‖₁。換句話說，在 L∞ 的限制下，一次泰勒近似的最佳解就是 FGSM，不是什麼經驗法則。

如果限制換成 L2（雜訊的總長度 ‖δ‖₂ ≤ ε），最佳解就變成沿著梯度本身的方向走：δ = ε · g / ‖g‖₂，這叫 fast gradient method（FGM）。所以「取正負號」是 L∞ 的產物，換了量距離的方法，最佳的一步也跟著換。

泰勒近似也解釋了為什麼梯度剛好接近 0 的像素在 GPU 上會「翻轉」（第 0 章）：那個像素的 gᵢ 幾乎是 0，它往哪邊走對 loss 幾乎沒有影響，但 sign 還是硬要選一邊，於是一點點捨入誤差就能決定它是 +8 還是 −8。這 200 張圖的 614,400 個梯度裡，沒有一個剛好是 0，所以 FGSM 改動了每一個像素值（除了被 0–255 剪掉的，第 1 章）。

2.3　為什麼這麼小的改動就夠：線性假說

每個像素只改 8，模型為什麼就認錯了？FGSM 的論文給了一個解釋，叫線性假說（linearity hypothesis）。看 g · δ = ε ‖g‖₁ 這個式子：ε 很小，但 ‖g‖₁ 是 3,072 個（32×32×3）梯度絕對值的總和。每個像素的貢獻都很小，加起來卻和維度成正比。對比一下隨機的雜訊：如果每個像素隨機 +ε 或 −ε，Σ gᵢ δᵢ 裡正負互相抵銷，總和大約只和維度的平方根成正比。維度越高，「對準梯度」與「隨機」的差距越大。這也是為什麼對抗樣本在高解析度的圖上更容易找：維度越高，同樣的 ε 能累積的效果越大。

實際量一下。在 resnet110 上，沿著 FGSM 的方向走 t 個像素值，和沿著一個隨機的 ±1 方向走 t 個像素值，比較準確率與平均 loss（浮點數圖片、沒有剪到 0–255；工具 docs/tools/hw10_ch02.py）：

三件事：

  • 方向比大小重要。只改 1 個像素值（0.4%），沿 FGSM 方向就讓準確率從 0.95 掉到 0.735；隨機方向改 1 完全沒有影響，改到 4 也只掉 1.5 個百分點。同樣大小的改動，對準了就有效，沒對準幾乎沒用。
  • 線性近似只在很小的範圍內準。「一次近似預測的 loss」欄是用 L(x) + g · δ 算出來的：t = 1 時預測 2.31、實際 1.63，已經差了不少；t = 8 時預測 16.9、實際只有 2.48。loss 沿著這個方向很快就彎下來了。所以線性假說說的是「起點附近的斜率很大」，不是「整條路都是直的」。這也是 I-FGSM 要走很多小步、每一步重新算梯度的理由：一大步出去，到達的地方和近似預測的差很遠（第 4 章）。
  • 效果大部分在第一個像素值就發生了。FGSM 從 t = 1 到 t = 8，準確率只多降了 14 個百分點，比 t = 0 到 1 的 21.5 個百分點還少。t = 2 和 t = 4 幾乎一樣（0.665 與 0.660）。這說明有一群圖很脆弱、輕輕一推就倒，另一群圖在 FGSM 的方向上相當頑強；要打倒後者，需要的不是更大的一步，而是更好的方向。

隨機雜訊在 t = 8 時也讓準確率掉了 10.5 個百分點（0.845）。這是另一個現象：這些模型沒有在帶雜訊的圖上訓練過，雜訊本身就是一種分布偏移。但它的效果遠不如同樣大小的 FGSM，到 t = 16 兩者仍差 25 個百分點。

2.4　ε 掃描：白箱與黑箱

把 ε 換成 1、2、4、8、16，用 resnet110 做 FGSM、存成 PNG，再量白箱（resnet110 自己）與 8 個受害者的平均準確率（實驗工具 docs/tools/hw10_exp.py，第 3 章介紹）。ε = 16 違反作業的限制，只是用來看趨勢；投影片 p.12 也放了 ε = 16 的圖讓大家看「看得出來」是什麼樣子。

「受害者 ensemble」是把 8 個受害者的 logits 加起來、取最大的那一類，模擬投影片說的「助教用一般模型的 ensemble」。它的原圖準確率 0.985，比任何單一受害者都高，被攻擊後也比 8 個的平均高一點：ensemble 本身就是一種防禦，第 5 章會從攻擊者的角度再用到這件事。

白箱與黑箱的曲線形狀很不一樣。白箱在 ε = 1 就掉了 21.5 個百分點，之後到 ε = 4 幾乎是平的；黑箱則是一路穩定往下，ε = 1、2、4、8 各降 7、5、6、15 個百分點。白箱一開始的大跌，是那群「輕輕一推就倒」的圖（2.3 節），而它們倒下的方式很依賴 resnet110 自己的細節，換一個模型就未必倒。黑箱的穩定下降，比較像是「雜訊越大、越多模型都受不了」。

最反直覺的是 ε = 16：黑箱的 0.267 比白箱的 0.315 還低。FGSM 用的是 resnet110 在原圖上的梯度，走了 16 這麼大一步之後，resnet110 的 loss 早就沿著曲線彎下來了（2.3 節：線性預測 33.5、實際 3.8），步伐超過了它的最佳點。別的模型的 loss 曲面不同，對它們來說同一個方向可能還沒到頂。這是第一個證據，說明「在代理上最有效」和「轉移到別人身上最有效」不是同一件事——第 4 章的 I-FGSM 會把這個問題放大到極端。

以 Simple 基準線（≤ 0.70）來看，ε = 8 的 FGSM 在本機黑箱上是 0.626，「應該」過得了。但本機黑箱只是近似，投影片也只說 Simple 的提示是 FGSM，沒有說哪個代理。第 3 章會看到，換一個代理模型，FGSM 的黑箱準確率可以從 0.57 到 0.72。

2.5　被騙成什麼

ε = 8 時，resnet110 原本答對的 190 張裡，有 71 張被 FGSM 騙倒（浮點數圖片；原本答錯的 10 張，沒有一張被「騙對」）。被騙倒的圖變成哪一類？最多的組合是：

真實類別 → 被認成張數
狗 → 貓11
飛機 → 鳥6
飛機 → 貓4
鹿 → 鳥4
汽車 → 青蛙3
貓 → 狗3
馬 → 貓3

狗變貓、貓變狗、飛機變鳥、鹿變鳥：大多是人看起來也有幾分像的類別。這很合理：非目標攻擊只是讓正確類別的 loss 上升，而 cross entropy 的梯度會把機率推給「目前第二高」的類別，通常就是最像的那一類。報告題的 dog2.png 被騙成貓（第 7 章），就是最常見的這一種。如果想讓狗變成卡車，就要做目標攻擊：改成讓「卡車」這一類的 loss 下降，代價是需要更大的改動。

2.6　FGSM 在今天

現在的做法：FGSM 很少單獨拿來攻擊，卻是對抗訓練的主力

今天的攻擊評估幾乎不再單用 FGSM：它只走一步，太容易被防禦騙過（第 7 章會看到原因），評估模型穩健性的標準工具是多步的 PGD 與 AutoAttack。但 FGSM 在另一個地方復活了：對抗訓練（adversarial training，訓練時把對抗樣本也放進去，讓模型學會不被騙）。用多步攻擊做對抗訓練非常慢，2020 年的 “Fast is better than free” 證明，只要 FGSM 從一個隨機起點出發，單步的 FGSM 對抗訓練就能達到接近多步的效果，速度快很多倍。對大型語言模型，對應的做法是在 embedding 上做一步梯度擾動來訓練（例如 FreeLB 一系列方法）。

本章重點

  • FGSM 對輸入取梯度，x + ε · sign(grad)：一步、梯度上升、只用正負號。loss.backward() 也順便算了所有權重的梯度，攻擊用不到。
  • 在 L∞ 限制下，一次泰勒近似的最佳解就是 ε · sign(g)；換成 L2 限制，最佳解是沿梯度方向（FGM）。
  • 線性假說：3,072 個微小改動對準了梯度就能累積成大效果；隨機方向的同樣改動幾乎沒影響（ε = 1：FGSM 0.735、隨機 0.95）。但 loss 只在起點附近接近線性，ε = 8 時一次近似把 loss 高估了近 7 倍。
  • resnet110 的 FGSM（PNG）：白箱 0.735／0.665／0.660／0.590／0.315（ε = 1／2／4／8／16），8 個受害者平均 0.891／0.843／0.778／0.626／0.267。ε = 16 時黑箱比白箱更低：在代理上的最佳一步，不等於轉移的最佳一步。
  • 被騙倒的圖大多變成相近的類別（狗→貓 11 張最多）。

自我測驗

1. 把 fgsm 的第 31 行改成 x_adv = x_adv - epsilon * grad.sign()（減號），會發生什麼事？

變成沿著梯度下降的方向走，讓正確類別的 loss 下降：模型會對每張圖更有信心，原本答錯的圖可能反而被「修正」成答對。白箱準確率預期會上升或持平（一大步走過頭時仍可能有少數例外）。這是推論，本書沒有實際跑。

2. 如果作業的限制改成 L2：‖δ‖₂ ≤ ε₂。FGSM 的第 31 行該怎麼改？

改成沿梯度本身的方向、把長度縮放到 ε₂：x_adv + epsilon2 * grad / grad.norm(p=2, dim=(1, 2, 3), keepdim=True)（每張圖各自除以自己的 L2 範數）。取正負號會讓 L2 長度變成 ε × √3072，違反限制。

3. 2.3 節裡，沿 FGSM 方向 t = 1 時準確率 0.735，t = 2、4 時是 0.665、0.660。為什麼 t 從 2 到 4 幾乎沒變？

FGSM 的方向是用原圖的梯度算出來的。對一部分圖片來說，這個方向一開始就讓 loss 迅速上升、很快越過決策邊界（t = 1、2 就倒了）；另一部分圖片沿這個方向走，loss 很快就彎下來不再上升（2.3 節的線性預測遠高於實際），走更遠也越不過邊界。要打倒它們，要在途中重新算梯度、換方向——這正是 I-FGSM（第 4 章）。

4. 把 loss_fn 改成 nn.CrossEntropyLoss(reduction='sum')，FGSM 存下的圖片會改變嗎？

圖片不會改變（在決定性模式下）。sum 與 mean 只差一個常數倍數 8，每個像素梯度的正負號不變，grad.sign() 完全相同。會變的是印出的 fgsm_loss：gen_adv_examples 用同一個 loss_fn 算 loss，再乘上 batch 大小累加（第 1 章），改成 sum 之後印出的數字會大 8 倍。這是推論，本書沒有實際跑。

5. ε = 16 時，8 個受害者的平均（0.267）比白箱（0.315）還低。這代表「用 resnet110 當代理，攻擊別人比攻擊它自己還容易」嗎？

不完全是。它代表的是：FGSM 這「一大步」對 resnet110 來說走過頭了（loss 曲線已經彎下來），對別的模型則剛好有效。如果改用針對 resnet110 的多步攻擊（I-FGSM），白箱準確率可以降到 0，遠低於黑箱。比較的是同一個方法在兩邊的效果，不是「誰比較容易被攻擊」。
