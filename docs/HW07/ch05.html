第 5 章　Medium：學習率衰減，以及訓練更久有沒有用

投影片給 Medium 的第一個提示是線性學習率衰減，只要加兩行程式。這一章把它加上去，和「不衰減」各用 3 個種子比較，再看訓練 1、2、3 個 epoch 的差別。結果是：衰減讓 dev EM 平均漲了 10 個百分點，遠大於種子之間的差距；訓練更久則幾乎沒有幫助，模型在訓練集上越來越準，dev 卻停在原地。最後用一組固定學習率的對照，拆開「學習率變小」與「最後降到 0」各自的作用。

5.1　TODO：兩行程式

train.py 的訓練迴圈裡，optimizer.zero_grad() 之後留著一行 TODO：「Apply linear learning rate decay」（第 3 章 3.3 節，train.py:107）。投影片 p.17 給了兩種做法：每一步手動把 optimizer.param_groups[0]["lr"] 減掉一點，或者用現成的 scheduler（排程器），並推薦 Hugging Face 的版本。本書的實驗工具用的是後者：

放進 train.py 的話，就是在建立 optimizer 之後加一行 scheduler = get_linear_schedule_with_warmup(optimizer, 0, len(train_loader) * num_epoch)，在 TODO 那一行寫 scheduler.step()，再從 transformers 匯入這個函式。get_linear_schedule_with_warmup 的三個參數是：優化器、warmup（熱身）的步數、總步數。warmup 是在一開始讓學習率從 0 慢慢升到設定值，本書設成 0，也就是從 1e-4 開始直線降到 0。實驗工具多處理了梯度累積（第 7 章），所以總步數要除以 accum，而且 scheduler 只在真正更新參數時才前進。

5.2　學習率怎麼變

投影片 p.17 特別叮嚀：訓練結束時，檢查學習率是不是非常接近 0。把同一個 scheduler 單獨拿出來，走完 991 步看看：

第幾步1100496900991（最後一步）訓練結束後
這一步用的學習率1.0e-49.0e-55.0e-59.3e-61.0e-70.0

每走一步，學習率減少 1e-4 / 991。最後一步用的是 1.0e-7，走完之後恰好是 0。整個 epoch 的平均學習率是 5.0e-5，正好是起點的一半。這個數字在 5.5 節會用到。

要注意兩個常見的錯誤。第一，總步數要給「整個訓練」的步數，而不是一個 epoch 的步數；如果訓練 3 個 epoch 卻給 991，學習率在第 1 個 epoch 結束時就降到 0，後面兩個 epoch 等於白跑。第二，scheduler.step() 要放在迴圈裡、每一步呼叫一次，放到 epoch 的迴圈外面就變成每個 epoch 才降一次。檢查的方法就是投影片說的：印出最後的學習率。

5.3　衰減 vs 不衰減：一個 epoch

只改這一件事，其他都照範例（1 個 epoch、舊版 AdamW、stride 150、範例的 evaluate），每種各跑 3 個種子：

1 個 epoch種子 0種子 1種子 2平均
不衰減（範例）0.4160.4820.4390.446
線性衰減0.5280.5660.5620.552

平均漲了 10.6 個百分點，而且衰減的三個種子全部高於不衰減的三個種子，兩組的範圍完全沒有重疊。這是第 3 章那把尺量得出來的進步：種子之間差 6.6 個百分點，衰減帶來的差距比它大得多。同一個訓練時間（991 步、大約 4 分半），換來的是第 0 章那條 Simple 基準線到 Medium 基準線之間的一大段（dev 與 Kaggle 不能直接比，見第 0 章）。

訓練時印出的 loss 也看得出差別。三個種子平均的訓練 loss，每 100 步一個點：

為什麼衰減有用？一個直觀的說法：學習率大的時候，每一步更新都很粗，參數在 loss 的谷底附近來回跳，停在哪裡帶有很大的隨機性；學習率慢慢降到 0，最後幾百步的更新越來越細，參數能穩穩地停在谷底附近。範例的 1e-4 對微調 BERT 來說偏大（BERT 論文建議的微調學習率是 5e-5、3e-5、2e-5），不衰減的話，訓練結束的那一刻參數還在大步移動。這個解釋還有一個漏洞：衰減也讓平均學習率變成一半。到底是「平均學習率變小」還是「最後降到 0」起作用？5.5 節用一組對照拆開。

5.4　訓練更久

投影片沒有規定訓練幾個 epoch，範例是 1 個。把不衰減的訓練延長到 3 個 epoch，並在每個 epoch 結束時評估 dev；衰減則分別以 1、2、3 個 epoch 為總長度各訓練一次（學習率在各自的最後一步降到 0）。每種設定 3 個種子：

設定種子 0種子 1種子 2平均
不衰減，1 epoch0.4160.4820.4390.446
不衰減，2 epoch0.4330.4790.4710.461
不衰減，3 epoch0.4730.5110.5140.499
線性衰減，1 epoch0.5280.5660.5620.552
線性衰減，2 epoch0.5430.5450.5620.550
線性衰減，3 epoch0.5640.5400.5350.546

（不衰減的 2、3 epoch 是同一次 3 epoch 訓練在第 2、3 個 epoch 結束時的評估：不衰減時，學習率固定，前 k 個 epoch 和「只訓練 k 個 epoch」完全相同。衰減就不同了，總長度不同，每一步的學習率都不同，所以要分開訓練。）

兩件事。第一，不衰減時，訓練越久越好，3 個 epoch 平均 0.499，但仍比衰減 1 個 epoch 的 0.552 低。第二，有衰減時，訓練 1、2、3 個 epoch 的平均分別是 0.552、0.550、0.546，差距不到 1 個百分點，比種子之間的差距小得多：多訓練的 epoch 沒有換來任何進步。訓練時間卻是 2 倍、3 倍。

多出來的訓練去了哪裡？看訓練集上的表現。衰減 3 個 epoch（種子 0）每個 epoch 最後 100 步的平均 loss 與 acc：

線性衰減 3 epoch，種子 0第 1 個 epoch第 2 個 epoch第 3 個 epoch
訓練 loss（第 800–899 批）0.5260.2520.084
訓練 acc（第 800–899 批）0.7630.8760.954
dev EM（epoch 結束時）0.5070.5470.564

到第 3 個 epoch，訓練集上的 loss 掉到 0.084、acc 95%，模型幾乎把訓練題目都背起來了；dev 的進步卻遠小於此，換其他種子甚至在第 3 個 epoch 下降（種子 1：0.545 → 0.540；種子 2：0.547 → 0.535）。這就是過擬合：從第 2 個 epoch 開始，模型看到的是已經見過的題目，它學到的越來越多是「這些題目的答案」，而不是「怎麼找答案」。第 6、7 章會換一個角度：與其讓模型重複看同一批題目，不如改變題目的呈現方式（隨機視窗），或從一個更懂中文閱讀理解的起點出發（換預訓練模型）。

這個結論會不會只是評估方式造成的？第 4 章發現，範例的評估（stride 150）會把很多本來能答對的題目弄丟。用第 4 章最好的評估（evaluate_v2、stride 16）重新評估同樣的 checkpoint：

線性衰減種子 0種子 1種子 2平均
1 epoch0.6980.7070.7060.704
2 epoch0.7120.7000.7130.709
3 epoch0.7130.7050.7000.706

評估改好之後，三種長度都到了 0.70 左右，彼此的差距仍然不到 1 個百分點。結論不變：在這份資料上，用 1e-4 加線性衰減微調 bert-base-chinese，1 個 epoch 就夠了。也順帶看到第 4 章的改進有多大：同一個衰減 1 epoch 的模型，範例的評估是 0.552，改好的評估是 0.704，差了 15 個百分點，比衰減本身帶來的 10.6 還多。

5.5　平均學習率，還是最後降到 0

線性衰減同時改了兩件事：平均學習率從 1e-4 變成 5e-5，而且最後降到 0。拆開的方法是加一組對照：學習率固定在 5e-5（衰減的平均值），不衰減，其他都一樣。

1 個 epoch平均學習率最後的學習率種子 0種子 1種子 2平均
固定 1e-4（範例）1e-41e-40.4160.4820.4390.446
固定 5e-55e-55e-50.5310.5200.5200.524
線性衰減 1e-4 → 05e-500.5280.5660.5620.552

從 0.446 到 0.552 的 10.6 個百分點，可以拆成兩段：學習率固定在一半（5e-5），就拿到了 7.8 個百分點；再把「固定」換成「從 1e-4 降到 0」，多拿 2.8 個百分點。所以範例最主要的問題是學習率太大，1e-4 對微調 BERT 偏高；衰減到 0 的收尾有幫助，但貢獻小得多，而且兩組的範圍有一點重疊（固定 5e-5 最高 0.531，衰減最低 0.528），只能說「大概有幫助」。

這也提醒我們讀投影片的提示時要多想一步：「加線性衰減」有用，不代表「衰減」是有用的那個部分。同一個改動常常同時改了好幾件事，就像第 3 章的兩種 AdamW 同時改了 eps、weight decay 與 eps 的位置。拆開它們要靠對照組，而對照組的設計，就是問「還有哪個更簡單的改動，也能達到一樣的效果」。

5.6　種子之間差多少，也會變

第 0、3 章一再強調種子雜訊，而本章的實驗顯示，雜訊的大小本身也跟設定有關。把每個設定三個種子的最高減最低列出來：

設定（範例的評估、stride 150）最低最高差距（百分點）
固定 1e-4，1 epoch（範例）0.4160.4826.6
固定 1e-4，2 epoch0.4330.4794.6
固定 1e-4，3 epoch0.4730.5144.1
固定 5e-5，1 epoch0.5200.5311.1
線性衰減，1 epoch0.5280.5663.8
線性衰減，2 epoch0.5430.5621.9
線性衰減，3 epoch0.5350.5642.9

範例的設定（學習率 1e-4、不衰減、1 個 epoch）恰好是雜訊最大的一個：6.6 個百分點。學習率小一點、或在結束前降下來，種子之間的差距就縮小到 1 到 4 個百分點。這和 5.3 節的直觀說法一致：學習率大，參數停在哪裡隨機性大，換一個種子（資料順序與問答頭的初始值不同）就停在別處。三個種子只能粗略估計雜訊，但這個趨勢說明了一件實務上的事：在一個雜訊很大的設定上比較改良，需要更多種子才看得出差別；先把學習率調到合理範圍，後面的比較會可靠得多。這也是本書之後的實驗（第 6、7 章）都以「線性衰減 1 個 epoch」為基礎的原因。

3 個 epoch 的衰減訓練中，每個 epoch 結束時的 dev EM 也畫成曲線，和不衰減的訓練放在一起：

現在的做法：warmup 加衰減，學習率小一點

今天微調預訓練模型，學習率排程幾乎都是「warmup 加衰減」：前幾百步（常見是總步數的 5% 到 10%）從 0 線性升到設定值，再線性或依餘弦曲線（cosine）降到 0。warmup 的用意是避免一開始問答頭還是隨機的時候，大的梯度把預訓練好的權重打亂。Hugging Face 的 Trainer 預設就是線性衰減（第 3 章 3.6 節的框）。微調 BERT 大小的模型，學習率多在 1e-5 到 5e-5 之間，比範例的 1e-4 小；微調大型語言模型時更小，用 LoRA 這類只訓練少量參數的方法時則常用 1e-4 左右。不管哪一種，訓練結束時學習率接近 0 是共通的做法。

本章重點

  • 線性學習率衰減只要兩行：建立 get_linear_schedule_with_warmup，每次更新後 scheduler.step()。總步數要給整個訓練的步數；結束時學習率應該是 0。
  • 1 個 epoch：不衰減平均 0.446，線性衰減平均 0.552，3 個種子的範圍完全不重疊。這是種子雜訊（6.6 個百分點）也蓋不住的進步。
  • 有衰減時，訓練 1、2、3 個 epoch 的 dev EM 平均是 0.552、0.550、0.546：多訓練沒有用。第 3 個 epoch 的訓練 loss 只剩 0.084、acc 95%，是典型的過擬合。
  • 不衰減時訓練越久越好（3 epoch 平均 0.499），但仍不如衰減 1 個 epoch。用第 4 章的評估（stride 16）重評，衰減 1、2、3 個 epoch 是 0.704、0.709、0.706，結論不變。
  • 固定學習率 5e-5 就有 0.524：衰減的 10.6 個百分點裡，7.8 來自平均學習率減半，2.8 來自最後降到 0。範例的主要問題是學習率 1e-4 太大。

自我測驗

1. 訓練 3 個 epoch，卻把 get_linear_schedule_with_warmup 的總步數寫成 991（一個 epoch 的步數），會發生什麼事？

學習率在第 1 個 epoch 結束時就降到 0，而 transformers 的線性排程在超過總步數後會一直維持 0（它的公式取 max(0, ...)），所以第 2、3 個 epoch 的每一步更新都是 0，參數不再改變。結果會和「衰減 1 個 epoch」幾乎一樣，只是多花了兩個 epoch 的時間。這是依程式推論，本書沒有實際跑。

2. 不衰減訓練 3 個 epoch 時，第 1 個 epoch 結束的 dev EM 為什麼可以直接當成「只訓練 1 個 epoch」的結果？衰減時為什麼不行？

不衰減時，每一步的學習率都是 1e-4，前 991 步做的事和「只訓練 1 個 epoch」一模一樣（第 2 章：資料順序由同一個種子決定；第 3 章：決定性模式），所以結果逐位元相同。實測 3 epoch 那次在第 1 個 epoch 的 dev EM 是 0.41588，和範例完全相同。衰減時，總長度 3 個 epoch 的排程在第 991 步的學習率還有 6.7e-5，而 1 個 epoch 的排程已經降到 0，兩者在第 1 步之後就不同了。

3. 衰減 3 個 epoch 的第 1 個 epoch 結束時，dev 平均只有 0.502，比「衰減 1 個 epoch」的 0.552 低。為什麼？

因為那時的學習率還很高（3 個 epoch 的排程走了三分之一，學習率還有 6.7e-5），而且沒有經過「最後一段小學習率」的收尾。這和不衰減的模型處境類似。換句話說，衰減的好處主要在最後那一段，中途評估看不到。

4. 有人說：「既然 3 個 epoch 的訓練 acc 有 95%，dev 才 0.546，加大 dropout 應該能改善。」這個方向合理嗎？本章的數據支持什麼結論？

方向合理：訓練與 dev 差距大是過擬合，正則化（dropout、weight decay）是標準的對策。但本章的數據顯示更省事的做法是「不要訓練那麼久」：衰減 1 個 epoch 的 dev 和 3 個 epoch 一樣好，訓練時間只要三分之一。加 dropout 能不能讓 3 個 epoch 超過 1 個 epoch，本書沒有實驗。
